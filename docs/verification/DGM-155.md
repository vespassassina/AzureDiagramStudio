## Owner Resize-Hit Repair Handoff — 2026-11-05

This was the first bounded repair of the distinct connector-path and
resize-handle hit-priority root. It did not renew the cross-item lifecycle
budget. Evidence, logs, exits and identities are in
`app/test-results/dgm155/resize-hit-repair/`; see `receipt.json`.

**Root cause.** Painter order uses `zIndexMode="manual"` and keeps boundaries
below connectors. Each React Flow node is its own stacking context, so a
selected boundary's in-node `NodeResizer` handles can never paint above edge
SVGs. A connector's transparent 20 px `.react-flow__edge-interaction` stroke
still receives `visibleStroke` hits, so it captured presses on the visible
handle.

**Fix.** These options were rejected:
- Raising the node, which changes paint order.
- Moving resizers out of the node, which breaks the DGM-153 resize capture and
  its locators.
- Blanket `pointer-events:none`.

`EditorSurface.tsx` now derives `resizeHandleClipPath`. When the editor is
writable and not presenting, it builds an even-odd clip path from the visible
corner-handle boxes:
- Selected boundaries contribute all four corners.
- Selected rectangles and text contribute the bottom-right corner only.
- Each box is 5 CSS px at the current zoom, centered on the corner, matching
  React Flow's handle.

The path is rendered as a canvas `<clipPath>`. `editor.css` applies it to
`.react-flow__edge` through `--dgm-resize-handle-clip`. Connectors keep hit
and paint everywhere else, including along resize border lines. Exports and
Present are unaffected.
