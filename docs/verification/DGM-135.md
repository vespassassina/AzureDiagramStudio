## Frozen Public Output Contract

The [manual](../manual.md#mcp-snapshot-and-export-source-only) freezes the exact
argument/options table, defaults, content schemas, MIME types and examples.
Both tools require the current nonempty `stateToken` (maximum 200 characters).
All schemas have object roots and reject unknown properties.

- `snapshot_diagram`: only `{stateToken}`; whole committed diagram PNG,
  scale 1, opaque diagram background, content bounds, normal export grid.
- `export_diagram`: `{stateToken, format}` where format is `svg`, `png`, `json`
  or `markdown`. SVG/PNG/Markdown accept optional scale 1/2, transparency,
  diagram/white background, content/16:9 aspect and explicit export grid.
  Scale controls rasterization; SVG remains vector, matching the UI.
  JSON accepts none of those image options.
- Optional `includeMarkdown` defaults false. True for SVG/PNG/JSON returns a
  single ZIP containing the diagram and exact companion description Markdown;
  true for Markdown and any companion option on snapshot are rejected.

Success is exactly:

```text
{content: [
  <payload>,
  {type: "text", text: JSON.stringify({
    stateToken: <captured token>,
    mimeType: <matching MIME>,
    filename: <safe suggested filename>,
    byteLength: <decoded byte count>
  })}
]}
```

Payload variants:

```text
PNG:      {type:"image", mimeType:"image/png", data:<canonical base64>}
SVG/JSON/
Markdown: {type:"resource", resource:{uri:<owned URI>, mimeType:<MIME>, text:<UTF-8 text>}}
ZIP:      {type:"resource", resource:{uri:<owned URI>, mimeType:"application/zip", blob:<canonical base64>}}
```

Text-resource MIME types: `image/svg+xml`, `application/json`, `text/markdown`.
Owned URI: `diagrammer://exports/<encodeURIComponent(stateToken)>/<filename>`.
It is inert; no resource-reading endpoint or filesystem object is implied.
The metadata byte count is decoded bytes, not base64 characters. Filenames use
the shared safe title stem and `.png`, `.svg`, `.json`, `.md` or `.zip`.

The entire UTF-8 serialized `{ok:true,output:<result>}` IPC envelope is limited
to **8,388,608 bytes**. Binary sizes are budgeted before base64; JSON escaping
and the complete envelope are checked before completion and independently in
main. Existing renderer pixel/dimension caps, 5 MiB document, 64 KiB HTTP request,
one pending broker operation, 4-second broker and 5-second HTTP deadlines remain.
Invalid arguments produce JSON-RPC `-32602`; state/runtime/render failures
produce explicit MCP `isError:true` text results. Malformed/late IPC replies
cannot complete successfully; a refused malformed reply leaves the bounded
request to expire unless a valid current reply arrives.
