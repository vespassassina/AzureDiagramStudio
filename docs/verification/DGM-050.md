### F-01: Resolved - Auto-arrange rejected annotations inside boundaries

**Original finding (High; retained history, not current behavior):**

Owners: DGM-010 domain guard and DGM-030 geometry integration; integrated regression belongs to DGM-040. Fails AC-06 and the mandatory absolute-position invariant for nested text/rectangles.

[commands.ts](../../app/src/document/commands.ts#L153) compares annotation objects including parent-relative x/y at [the semantic guard](../../app/src/document/commands.ts#L161). [layout.ts](../../app/src/layout.ts#L102) correctly rebases those coordinates at [line 104](../../app/src/layout.ts#L104) to keep the annotation's **absolute** position unchanged when its boundary moves. The guard rejects that valid result. [session.ts](../../app/src/app/session.ts#L197) routes the result through this guard.

Cheap live repro, independently executed in a fresh Edge context at the production URL:

1. In the default Commerce platform sample, select its text note and set Parent boundary to Application layer.
2. Select Down layout and click Auto-arrange.
3. Observe `result.diagram: Layout may change only structured entity geometry, routes and direction; content, annotations and membership must remain unchanged`.

The entire durable document remained identical at revision 2, including the reparented note (local x=24, y=452). Thus work is protected, but the required layout operation cannot complete.

A separate native Node probe set the sample note's parent to `application`, local x=24/y=170/width=200, then called `computeLayout(original, 'DOWN', original.revision)` and `applyCommand(original, {type:'applyLayout', expectedRevision:original.revision, result})`. Absolute position stayed (388,306); the computed local position became (303.33333333333337,-117); application rejected with `DomainError`, code `invalid-command`, and the message above. No production code or tests were changed.

Coverage gap: [layout.test.ts](../../app/src/layout.test.ts#L61) checks nested annotation geometry from the pure computation, but does not apply its result through the domain command. [commands.test.ts](../../app/src/document/commands.test.ts#L118) tests the command without this annotation rebasing case. Green existing tests therefore do not disprove the defect.

**Repair verification:** [commands.ts](../../app/src/document/commands.ts#L153) now normalizes annotation x/y only for semantic comparison and separately compares complete-parent-chain absolute positions within `1e-6`. Annotation ID, kind, label/subtitle, icon, status, color, layer, parent membership and exact width/height remain guarded. Components/boundaries may change geometry, connections may receive routes, and direction may change; document metadata and connection semantics still cannot change. Snapshot/result/current revision guards remain intact. This is a targeted coordinate rebase, not removal of the annotation invariant.

The **52 added tests** in [commands.test.ts](../../app/src/document/commands.test.ts#L142) run real `computeLayout` then `applyCommand`: text/rectangle, RIGHT/DOWN, root-parent and tier-two boundaries, negative absolute coordinates, actual UI-equivalent reparent commands, exact one-step undo/redo and immutable inputs.
