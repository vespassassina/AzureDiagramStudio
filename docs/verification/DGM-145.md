1. **Default arrangement window — PASS.** The deterministic broker test sends
   `start + 15,000ms`, remains active at 4,000ms, and accepts a valid completion.
   A supplemental probe confirms acceptance of a successful result at 4,000ms.
2. **All other deadlines and output cases — PASS.** Snapshot and PNG export
   tests assert `start + 4,000ms` and reject results after expiry. The additional
   operation matrix covers every remaining supported mutation at that same
   deadline and rejects each late result.
3. **Arrangement expiry/boundary — PASS.** The fake-clock test advances exactly
   15,000ms, observes timeout/cancellation, inactive state, and rejection of a
   late result.
4. **Cancellation, unload, stale work, and retry — PASS.** The broker test
   covers abort and `clear()` during the longer window, rejects late results,
   then accepts a fresh request. Unchanged renderer tests cover unload
   cancellation without late completion, session deadline/guard rechecks,
   serialized mutations, and stale layout results without document/history
   mutation.
5. **Override, validation, and single-flight — PASS.** A supplied 30ms timeout
   remains authoritative for arrangement. Existing deterministic broker tests
   reject invalid requests and overlaps before dispatch.
6. **Renderer/native budget — PASS.** Renderer source and tests are unchanged.
   The rerun confirms the existing 15,000ms native worker timeout, worker
   termination, cancellation, and retry behavior; no synthetic broker success
   is used to bypass renderer acceptance.

The manual now describes 15 seconds for arrangement and 4 seconds for snapshots,
exports, and all other mutations; HTTP and output limits remain unchanged.
