### Source Trace And What The Original Failure Does Not Prove

The original helper waits for the main canvas, counts nodes, immediately probes
New diagram visibility, optionally sends Escape, waits for Saved, writes the
sample fixture, arms the chooser promise and clicks Open JSON. These are separate
asynchronous steps, not an atomic startup-readiness check.

- `src\app\session.ts:130–145` publishes the fresh-start offer only after the
  owned storage load, initially reports saving, then schedules the first save.
- `src\editor\EditorSurface.tsx:1051–1063` opens and acknowledges that offer in
  an effect. The main canvas existing is not proof this later modal has settled.
- Open JSON calls `fileAction` (`EditorSurface.tsx:905`), then `choose`
  (`src\App.tsx:37–40`), which checks mutation ownership and invokes the hidden
  `Open document file` input. A real toolbar click, not direct storage injection,
  must reach that chain.
- The final adapter awaits `page.waitForEvent('filechooser')` only after awaiting
  the toolbar click. A rejected chooser can therefore terminate Node before the
  pending click failure and outer report/cleanup are retained.

A late New diagram modal intercepting the toolbar click is consequently a
specific **hypothesis**, not a demonstrated cause of the historical failure.
The retained `general-x64-final` stderr proves the 30,000ms chooser timeout and
unhandled rejection; it contains no click-actionability log, startup-modal
snapshot or renderer timeline to establish which upstream step prevented it.
