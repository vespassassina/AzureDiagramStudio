## Acceptance checks

1. **PASS — preset controls, grid separation, and keyboard/pointer access.**
   Actual pointer operations reached all four presets at 1440×900, 390×844,
   and 1280×520 in both themes; grid remained a separate group. Keyboard
   activation and reset-to-absent passed across the same six combinations.
   Evidence: `browser-report.json`, `preset-keyboard-report.json`, and
   screenshots `desktop-{light,dark}.png`, `narrow-{light,dark}.png`, and
   `short-{light,dark}.png`.
2. **PASS — single-edit history and document preservation.** A real Paper
   selection advanced revision once; Undo restored the absent field and Redo
   restored Paper. On the Web/API starter (14 entities, 10 connections), the
   background change preserved semantic document content and grid, camera, and
   the unchanged empty selection. Evidence:
   `browser-report.json` and `sample-export-report.json`.
3. **FAIL / PARTIAL — color state, mixer, and drafts.** Valid `#RGB` JSON
   round-tripped, external JSON replacement updated the background, hex field,
   and Paper pressed state, and hex edits synchronized to the mixer. Escape,
   invalid input, reset, and one-commit finish passed in the browser/focused
   UI tests. However, saving `#fff` left the visually white White preset
   unpressed while Solid color was pressed (`ui-gap-report.json`), so the
   selected preset indication is inconsistent for an accepted shorthand color.
   In dark theme, the selected light-blue swatch’s white check and green outline
   measured only **1.21:1** and **1.41:1** respectively
   (`swatch-viewport-report.json`), making the selected state difficult to
   distinguish. Hex-to-mixer synchronization passed; actual native-picker
   interaction to establish mixer-to-hex synchronization was not completed,
   so that direction remains unverified (not counted as a product failure).
4. **PASS — validation and persistence.** The browser saved and reopened
   `#fff`, imported a separately changed JSON document and refreshed the
   controls, and saved/reloaded `#2f5597`. Focused validation, MCP schema, and
   renderer session tests passed. Evidence: `rgb-background.json`,
   `external-background-change.json`, `background-roundtrip.json`,
   `ui-gap-report.json`, and the focused test logs.
5. **PASS — default exports and representative output contracts.** Actual
   downloaded SVG and PNG default exports matched saved White, Paper, and
   custom `#2f5597` backgrounds (`solid-default-export-report.json`). Actual
   transparent SVG had no full-canvas fill; PNG 1× and 2× had zero-alpha
   canvas pixels at the expected dimensions; White override was opaque white.
   The representative starter export contained 14 entities and 10
   connections, and no checkerboard was exported
   (`sample-export-report.json`). Focused MCP session tests exercised PNG,
   SVG, JSON, Markdown, and ZIP packaging, including inline Markdown image
   content, `.zip` filenames, output options, and unchanged session state.
   Evidence: `sample-transparent.svg`, `sample-transparent-{1x,2x}.png`,
   `sample-white-override.png`, `white-default.{svg,png}`,
   `paper-default.{svg,png}`, `custom-default.{svg,png}`, and
   `mcp-session-run.log`.
6. **FAIL — transparent legibility.** The transparent editor showed its
   checkerboard, contained no parser `NaN`, and omitted the checkerboard from
   exports. Present retained the saved transparent background and 14 entities.
   But in dark theme the “Azure web & API” heading measured **1.31:1** against
   dark checkerboard squares, so the “content stays legible” requirement is not
   established. Evidence: `transparent-legibility-report.json`,
   `transparent-header-legibility.png`, and `sample-export-report.json`.
7. **PASS with test-scope note — read-only/loading/Present guards.** Focused
   UI tests verified the background mixer/reset are disabled and cannot commit
   in read-only mode, Present disables the mixer and blocks commands, and the
   existing loading mutation guard passes. The shared `writable` gate disables
   background controls for read-only/loading/Present and `emit`/`preview`
   reject guarded mutations. Loading was not separately exercised in a live
   browser session. Existing loading/recovery behavior passed its focused
   recovery test. Evidence: `background-editor-tests.log`,
   `recovery-tests.log`, and the `writable`, `editMetadata`, `emit`, and
   preset-control paths in `app/src/editor/EditorSurface.tsx`.

## Findings

- **DGM146-V1 — shorthand preset state mismatch (AC3).** When a valid `#fff`
  background is saved and reopened, the White preset reports
  `aria-pressed=false` and Solid color reports `true`, although the displayed
  background is white. Evidence: `ui-gap-report.json`.
- **DGM146-V2 — selected swatch indicator has low contrast (AC3).** On a
  `#ddebf7` swatch in dark theme, the white check is 1.21:1 and the focus
  outline is 1.41:1 against the swatch. Evidence:
  `swatch-viewport-report.json`.
- **DGM146-V3 — transparent heading loses contrast in dark theme (AC6).** The
  transparent editor heading is 1.31:1 against dark checkerboard squares.
  Evidence: `transparent-legibility-report.json`.
- **DGM146-G1 — native picker to hex synchronization is open.** A browser
  `fill()` on `<input type="color">` is not a native-picker interaction and was
  not used to infer product behavior. A real picker interaction is still
  needed to close this verification gap. The inconclusive experiment is
  retained as `app/test-results/DGM146/verifier/mixer-fill-inconclusive-attempt.json`.

No finding was repaired by the verifier. These results do not authorize a
release, installation, or modification of the running 0.5.0 application.
