This is not a stroke-width issue, a scene/export discrepancy, a missing
connection, or merely a compound-coordinate translation error:

   `100 + routed.length*80 + labelHeight`. Actual module reserves are
   **284, 604, 684, 364px**; the root reserves **604px**.
2. With real ELK **INTERACTIVE** placement and explicit cross-axis ports, routing
   dummy tracks can remain at **24px** while real units retain the large shared
   coordinate. For Prepare, the local ELK section itself travels from x858 to
   x943, then to **x24**, then to the target x618. The detour therefore already
   exists inside ELK output; it is not introduced by later route concatenation.
   The envelope includes internal routes and grows Engineering to 967px wide.
3. Outgoing/incoming external proxies are partitioned before/after all content
   according to content flow, not peer group position. For DOWN contents this
   exposes bottom/top boundary ports, even where an explicitly left-facing
   component could use the adjacent horizontal corridor. In the root's real
   ELK output, Extract runs from `(312,849)` to `(613,849)`, then **`(613,24)`**,
   then **`(1273,24)`**, before reaching the Engineering proxy at `(1273,618)`.
   Query has the same upper excursion. Root groups remain at y618.
4. The captured flat module edge containers are their graph root, not displaced
   child containers. Rendered, exported and MCP paths match exactly. Correcting
   an origin or changing export rendering cannot shorten these actual sections.

### Root Cause And Correction

The previously demonstrated cause was the coupling of aligned compound
placement to proxy/dummy routing tracks and large common transverse reserves,
not rounded rendering, connection thickness or incorrect absolute coordinates
alone. Reducing reserves or moving proxies broke the accepted placement/exit
invariants. Standard DOWN also had header crossings.

`computeLayout` now retains the existing directed/stacked real-ELK placement
and passes the completed diagram to pure `routeFixedGeometry`. This stage
replaces connection points/label positions only. It never translates, resizes
or reparents objects to accommodate a path. `layout-stacked.ts` remains
byte-identical to the accepted helper.

- `routing-geometry.ts`: absolute component/boundary rectangles, full-width
  header obstacles, ancestors, cardinal face points/stubs and normalization.
  An explicit side is never rewritten. Its position *on that same face* may
  move toward a feasible local corridor; an unspecified side uses peer geometry.
- `routing-search.ts`: finite obstacle/channel grid; segment-midpoint obstacle
  rasterization; deterministic heading-aware A* with Manhattan length, 12px
  bend cost and occupied-channel penalties. Parallel routes introduce 20px
  alternative tracks. Label feasibility is part of the search state.
- `routing.ts`: stable port planning, ancestor exit-only/entry-only gates,
  measured label reservations, route normalization and final independent
  geometry audit. All connections succeed together or the entire layout throws.
  There is no missing-edge success or fallback to old invalid ELK routes.
- `layout-worker.ts` and `app/browser.ts`: the entire placement **and** routing
  job runs in an owned module worker, with the existing 15-second deadline and
  cancellation terminating that worker. The worker uses official `elk-api.js`
  with official `elk-worker.min.js` child transport, not bundled fake-worker
  construction. This is necessary in Electron's nested-worker environment.

No scene/export/MCP output renderer, public API, schema, dependency, menu,
Favorites, root preference, appearance or persistence implementation changed.
No second mutable diagram model was introduced.
