## Context And Authority

The PO requested: "for the diagram background, give me more options to select
and for plain color give me a color mixer or swatches like excel."
The PO approved the proposed scope: solid-colour picker with an Excel-style
swatch palette plus a custom colour mixer, White, Paper and Transparent
presets; grid controls separate; chosen background preserved in JSON and
SVG/PNG exports. This is an extension of existing Document properties, not a
new settings panel or visual redesign. Read docs/ui-design.md and lessons.md.

## Interfaces And Contracts

- One background control group in Document properties, reachable by the
  existing View/Commands/context entrypoints. Preserve reset-to-default.
- Presets: White (#ffffff), Paper (#faf8f3), Transparent (no canvas fill),
  and Solid colour. Paper is a flat colour, not a texture.
- Solid colour: labelled theme-like columns with light/dark variations plus
  a standard-colour row, selected-state indication independent of colour,
  in-app RGB mixer with sliders/numeric channels and editable validated
  #RGB/#RRGGBB field. After independent review, the PO explicitly chose
  "Use the in-app RGB mixer (Recommended)" instead of depending only on the
  operating-system colour dialog. Retain the existing native picker as a
  supplementary affordance if useful; it is not the sole verified custom mixer.
  No Excel assets, proprietary UI copying, new dependency or global preferences.
- Reuse existing backgroundColor optional string. Extend its accepted values
  narrowly to the literal "transparent" for the approved transparent preset;
  no schema-version bump. Existing absent and hex-colour documents retain
  their current semantics. Expose/document this additive value consistently
  across native JSON validation, metadata mutation and desktop/MCP schema
  validation. Invalid CSS, alpha hex, URLs and arbitrary strings stay rejected.
- Scene rendering must separate transparent fill from the opaque reference
  used for contrast calculations. Transparent shows a checkerboard only as
  an editor/preview affordance, never in exported content or JSON.
- Default Diagram exports honour the saved preset; explicit White export
  overrides it, and explicit Transparent export removes fill. SVG/PNG,
  Markdown embedded PNG, ZIP companions and MCP outputs share these semantics.
- Existing grid settings, clipping, contrast, framing, selection and limits
  stay intact. Reset restores the original absent-field behaviour, including
  the light editor's workspace-only paper tint and white default exports.
- Use existing command/preview/history/autosave paths. Swatch/preset clicks
  are atomic undoable edits. Mixer/hex drafts preview; finishing commits one
  change, cancellation restores prior document without history mutation.
- Preserve read-only/loading/Present and export safety guards, selection,
  camera, draft/focus behaviour and recovery. No silent invalid-input fallback.
- Source-only delivery: no version bump, build package, release, Git delivery,
  installation or replacement of the running0.5.0 executable is authorized.
  The repair implementer nevertheless created local commit `f4eeb5e` against
  its no-Git instruction. It is preserved rather than reset/amended, was not
  pushed, and does not represent PO-authorized source delivery or publication.

## Given / When / Then Acceptance

1. Given Document properties, all four choices and reset are labelled,
   keyboard reachable and operable by actual pointer at desktop,390px narrow
   and short viewports in light/dark themes. Grid remains a separate group.
2. Given a preset or swatch, choosing it changes the canvas and commits exactly
   one metadata edit. Undo restores the complete prior document and Redo restores
   the choice. Other objects, grid, camera and selected content are unchanged.
3. Given Solid colour, swatches show meaningful names/hex and selected state;
   the in-app RGB sliders, numeric channels and hex field stay synchronized.
   Channels accept only integers0-255 and reject malformed values explicitly.
   Valid drafts preview,
   finish commits once, Escape cancels; invalid hex reports an error without
   committing. External document changes/reset do not leave stale controls.
4. Given any saved preset/custom hex, native JSON save/open and autosave/reload
   preserve it; malformed inputs fail explicitly. Old absent/#RGB/#RRGGBB
   inputs preserve behaviour. Main/renderer MCP validation agree.
5. Given Paper/White/custom/Transparent, actual SVG/PNG default Diagram export
   reflects that choice. Transparent has zero background alpha and no
   checkerboard pixels; White override is opaque white. Verify PNG1x/2x,
   SVG and representative Markdown/ZIP/MCP output with unchanged grid settings.
6. Given transparent editor/preview, checkerboard indicates transparency but
   content stays legible and there is no colour-parser NaN. Explicit dark/light
   colours keep shared contrast handling; Present uses saved background.
7. Given read-only/loading/Present, no background command can bypass guards.
   Existing opening/closing/focus/draft/history and export safeguards remain.
