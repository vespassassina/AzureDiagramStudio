# DGM-127: Unified New Document And Template Picker

Date: 2026-10-19. Status: COMPLETE FOR APPROVED SOURCE SCOPE / INDEPENDENT SELECTED BROWSER ACCEPTANCE PASS.
Authority: PO requested "for a new document button use a unified new document
and template picker" and "when starting fresh, show the empty canvas and the
template picker. default to empty canvas".

## Context And Scope

The editor already has one New diagram chooser with Blank and eleven starters,
but a fresh workspace currently loads the commerce sample and does not show
that chooser. Make the existing chooser the unified entry point for fresh
startup and the New diagram button/command. Do not add a second picker or
another startup document screen.

Fresh means a successful storage read returns no saved diagram and this session
owns editing. Recover saved diagrams, including saved empty diagrams, unchanged
without automatically opening a picker. Storage/lock errors must not look like
a successful fresh start or overwrite recoverable work.

## Behavior And Internal Interfaces

- Before recovery completes, show a non-mutating empty loading canvas rather
  than flashing the commerce sample. Preserve loading/read-only/error handling.
- On successful first writable no-document load, establish a fresh empty
  document and show the unified picker over its empty canvas once.
- Blank is the default: visually clear and initially keyboard-focused so Enter
  starts an empty canvas. No template is applied without an explicit choice.
  Closing, backdrop dismissal or Escape on fresh startup leaves the empty
  canvas usable. It does not load the sample or dirty a template.
- The ordinary New diagram button and Commands action open this same picker
  with Blank as default, preserving the current diagram/drafts until a choice
  is accepted. Cancel preserves all existing state. Retain New diagram's
  established accessible label and existing template names unless necessary.
- A chosen template remains a detached fresh copy through existing validated
  starter callbacks. The existing dirty replacement confirmation still protects
  real unsaved work; cancel/reject never discards or commits a pending draft.
  A pristine fresh blank must not demand a discard confirmation before its first
  template selection.
- Startup picker intent is session UI state, never a new saved diagram field.
  If internal session-to-editor props/callbacks are needed, keep them optional
  and backwards-compatible for existing harnesses. Do not change native JSON,
  public import/export, storage schema or persistence keys.
- No duplicate startup picker under React StrictMode, late storage completions,
  remounts or lock reacquisition. Never open automatically in loading, read-only,
  failed recovery or Present. Existing About/Help/other modal guards still hold.
- Desktop, 390x844 and 720x450, both themes: modal/Blank/close/templates remain
  reachable, Tab is contained, arrows navigate and Escape closes. Keep template
  previews, guide descriptions, selection validation and existing tour behavior.
