Publish a normal latest GitHub release tagged exactly `0.3.0`, containing current
About, empty-start/unified picker and verified harness changes. Set app/package
metadata to 0.3.0 without dependency upgrades. Commit/merge/push the exact release
source using the existing default branch and no PR, then tag that source after
artifact/runtime acceptance. The tag is not `v*`, avoiding unrelated automatic
Mac release attachment. Do not replace any existing tag, release or asset.

Deliver exactly:

- `Azure-Diagram-Studio-0.3.0-win-arm64-portable.exe`
- `Azure-Diagram-Studio-0.3.0-win-x64-portable.exe`
- `SHA256SUMS.txt`
- `SOURCE-PROVENANCE.json`

Use the existing portable packaging and Electron policy. Signing credentials
have not been supplied: do not acquire certificates, access signing secrets,
change security/CI, claim signed binaries or bypass operating-system warnings.
The release is unsigned unless actual authorized signing evidence exists.
Do not add Mac/Linux packages or promise native Intel/AMD qualification from
ARM64-emulated execution. No storage/schema/user-profile migration.

## Roles And Serial Execution

Orchestrator owns spec/docs, source merge/push, annotated tag and release state.
One implementer prepares version metadata and a directly coupled correction of
the existing hard-coded 0.1.0 checksum helper, under RED/GREEN; dependencies,
application behavior and public contracts are unchanged.

Pause after source preparation so the orchestrator can commit/merge/push the
exact candidate. The same owner then builds both targets sequentially in a new
isolated release cell from that commit, preserving existing dist/stage/release,
evidence and user profiles. Reuse installed pinned dependencies; no unnecessary
install or upgrade. Pinned architecture runtime downloads are permitted.
Exclude signing credentials from build environments. Use short fresh owned
runtime profile paths; retain provenance, first failures and cleanup evidence.

An independent verifier launches each exact new EXE, never source/unpacked
Electron, and checks identity, embedded architecture, secure local origin,
assets/worker/layout/history, JSON/SVG/PNG, persistence/relaunch, About 0.3.0,
fresh Blank/template picker and saved-work recovery. Reuse appropriate existing
desktop tests; preserve first failures. Product/security defects are reported,
not silently repaired or weakened. Maximum three bounded repair cycles.
Verifier never fixes implementation. Shared-file/terminal operations stay serial.
