# DGM-165: Publish The Latest Accepted Windows Source

Authority: PO request, 2026-11-06: "compile and publish latest".

## Scope And Plan

Publish the accepted DGM-163 workbook/menu UI and DGM-164 architecture catalog
as a distinct **0.5.3** Windows release, following the existing patch-release
cadence. Preserve the published 0.5.2 release, tags, binaries and open previews.
Use the established Windows ARM64 and x64 unsigned portable targets; no Mac,
new dependency, signing, CI/security policy or feature change.

One release implementer updates app/package version metadata and compiles,
stages and packages both targets serially with retained first logs and
source/staged/output hashes. Reuse accepted feature tests rather than restart
the source UI matrix. One independent verifier qualifies the exact packages
through owned isolated GUI/MCP instances, not portable-bootstrapper stdio.

The orchestrator then commits only relevant source, version and documentation,
fast-forward pushes the current and established default branches, creates a
new annotated 0.5.3 tag and publishes both executables plus SHA256SUMS as the
stable latest GitHub release. No PR, force push or existing-tag replacement.
Fresh public downloads must match the qualified sizes and hashes.

## Acceptance

- Version metadata, staged app and both actual runtimes report 0.5.3.
- Current desktop boundary tests and TypeScript/Vite build/staging pass.
- Both ASARs match accepted staged inputs, including the 35-template catalog.
- Exact ARM64 and x64 GUI/MCP smoke checks cover template discovery, new
  architecture content/Markdown and representative workbook JSON/PNG output.
  x64-under-ARM64-emulation is labeled honestly.
- Commit/tag/release source provenance and public-download hashes match.
- Native Visio and real native chooser limitations remain disclosed, not
  reopened or called passed. Existing profiles/windows/drafts remain untouched.

Routine release documentation is consolidated against final receipts.
Packaging/publication failures are retained; release completion is not claimed
until external assets are confirmed.
