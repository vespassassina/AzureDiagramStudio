## Context and Local Evidence

Provide a small selection-only spacing correction, not another layout engine. The card permits alignment/distribution but leaves anchor, center, mixed-parent and containment behavior unresolved. The following choices are explicitly PROPOSED, not adopted decisions.

- [Selection helpers](../../app/src/editor/interactions.ts): `selectionRoots` removes objects with selected ancestors, retaining document entity-array order. `movePositions` takes the first root's drag delta, grid-snaps it and applies that same delta to every root. It cannot express independent alignment/distribution targets and must retain its existing drag/nudge behavior.
- [Public command contract](../../app/src/contracts.ts) and [document entry point](../../app/src/document/index.ts): use the existing `{ type: 'move', positions: [{ id, x, y }] }` command and `applyCommand`. Coordinates are parent-relative, not canvas-absolute. No new command variant, exported API, dependency or configuration is proposed as already approved.
- [Move owner](../../app/src/document/commands.ts): validates a detached draft, filters selected descendants, invalidates route caches, expands ancestors for moved children, and publishes one revision. An unchanged raw move can still advance revision. Do not dispatch no-op moves or assume ancestor growth can be switched off.
- [Geometry](../../app/src/model.ts): `absolutePosition` sums the complete parent chain. [Validation](../../app/src/document/validation.ts) checks finite geometry, references, depth and routes, but is not a containment oracle. `expandAncestors` additionally requires 24-unit side/bottom padding and child top clearance of `entityTextGeometry(parent).textBottom + 24`.
- [Editor dispatch](../../app/src/editor/EditorSurface.tsx) and [session](../../app/src/app/session.ts): existing draft/commit guards and `canMutate` protect storage ownership and Present independently; session command dispatch commits through existing history. Domain commands alone are not permission guards.

Local hypothesis: independent absolute targets can be translated back to each unchanged immediate parent and applied by one existing move, provided a pure preflight rejects every candidate that would alter container geometry or unrelated content. Cheapest disconfirming check: the unequal-width nested fixture below, compared with the actual detached `applyCommand` result, exposes shared-delta, snapping, ancestor-expansion or coordinate errors.

## Proposed Interfaces and Behavior

1. Effective selection is existing entity selection reduced through `selectionRoots`. Require at least TWO roots to align and THREE to distribute. All roots must share the same normalized immediate `parentId` (`undefined`/`null` both mean canvas). Selected descendants do not count toward either minimum. A selection containing any connection, unknown ID or duplicate ID is ineligible; do not silently operate on a subset. Mixed-parent roots are unavailable, including canvas plus a nested child; common ancestry is not enough.
2. PROPOSED actions are Align left, Align center (horizontal center only), Align top, Distribute horizontally and Distribute vertically. No right/bottom/vertical-center action is implied. PROPOSED alignment reference is the first effective root in document entity-array order, not click order, z-order, smallest ID or selection-bounds center. Keep that reference fixed. Left/top use its absolute bounding-box edge; center uses its absolute `x + width / 2`. Preserve the other axis and all dimensions. Use canonical current dimensions, not DOM measurements or newly measured/shrunk geometry.
3. PROPOSED distribution uses equal nonnegative edge-to-edge gaps, not equal centers. Sort by absolute leading edge on the chosen axis; ties use original document entity-array order. Keep the first and last sorted roots at their original positions. Gap = (last trailing edge - first leading edge - sum of root sizes) / (root count - 1). Position interiors cumulatively from the first trailing edge plus that gap. Zero gap is permitted; negative gap, nonfinite results or a candidate requiring containment changes is rejected atomically. Preserve the other axis; no obstacle avoidance is promised.
4. Target computation is pure: current validated diagram, entity selection and one of the five actions produce either independent existing move positions or an ineligible/no-change result. This is a behavioral proposal, not a frozen new exported function/signature. Calculate in absolute coordinates, then subtract each root's complete unchanged parent origin. Do not pass these targets through shared-delta `movePositions`, round to grid, or change grid settings. Exact fractional positions with snap on/off are a PROPOSED explicit alignment policy requiring PO approval.
5. Preflight the entire operation before dispatch. For nested roots, every candidate must fit its current parent's text/header clearance and 24-unit side/bottom margins; the complete affected parent chain must remain unchanged. Compare a detached existing-command result with the requested geometry before publishing: reject if any width/height, parent origin, membership, text, asset, order, metadata or unrelated entity would change. A selected boundary moves its subtree rigidly: descendants keep their local geometry and inherit the boundary delta exactly once. Unselected objects outside selected subtrees keep both local and absolute geometry. This exception for carried descendants is not permission to move unselected siblings or compensate them by editing coordinates.
6. No implicit group growth, shrinkage, reparenting, clipping or clamping. If the existing move would expand/shift a boundary or normalization would change protected fields, return an ineligible result with a concise reason and publish nothing. Already-arranged geometry also publishes nothing, preserving revision/history/autosave. Availability and execution must use the same rules and current snapshot; after draft completion, re-evaluate selection, document/revision and eligibility before committing. Invalid/IME-composing drafts block the action. Stale document/selection or ownership/Present transitions cancel it rather than applying stale targets.
7. A real accepted action sends one move through existing editor/session command handling: one revision and one undo step, exact undo/redo snapshots, unchanged selection/camera/tool. Preserve connector IDs, endpoints, sides and semantics. Accept existing move invalidation of cached `points`, `routeRevision` and `labelPosition`, including unrelated caches; do not falsely promise cached routes survive. The shared renderer must produce valid finite attached endpoints without running ELK. Rejection/no-op retains the original caches; undo restores the original document including routes.
8. Contextual selection controls reuse existing Lucide/icon-button/tooltips and command-menu dispatch conventions. Hide the cluster below two effective entity roots or during Present; with two roots distribution is disabled. Mixed-parent/read-only/otherwise ineligible selections expose disabled controls with a reason; every invocation, including command-menu callbacks, rechecks guards. No new shortcut or explanatory in-app panel. Existing compact responsive/focus behavior remains; keyboard activation uses the same action as pointer activation.
