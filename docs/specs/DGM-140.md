Date: 2026-10-28. Status: COMPLETE / INDEPENDENT SOURCE ACCEPTANCE PASS.

it exists at the bottom, and normal top File/View/Settings dropdown menus,

(Recommended)".

## Context And Contract

Replace the individual top application/file/view controls with conventional
in-app File, View and Settings dropdown menus, usable in desktop and browser.
Keep branding/document title and the three menu triggers; the top action-button
group contains only Undo, Redo, Export and Present. No duplicate top New/Open/
Import/Save/Help/About/Settings/theme buttons. Do not remove these capabilities.

- File: existing New diagram, Open JSON, Import skill JSON and Save JSON actions.
- View: existing panel visibility, theme and applicable existing display/fit
  options; reuse actual commands rather than creating new display behavior.
  Keep menu labels/state meaningful and avoid exposing unsupported actions.
- Settings: existing Settings dialog, Help guide and About dialog.

The existing canvas Auto-arrange dropdown and square Sidebar button remain
beside the edit area. Existing drawing tools and useful contextual canvas
navigation are not removed. Explicit local panel controls and conventional
View menu commands may coexist as contextual and application-level access.
Do not silently remove Commands/shortcuts or change layout algorithms.

Remove the duplicate top save-status display, not persistence behavior or error
reporting. The existing bottom status remains the canonical visible location
for loading/saving/saved/error/ownership messages. Ensure actual errors are still
visible and accessible; do not hide errors because the top status was removed.

## Interaction And Accessibility

Use actual accessible menubar/menu semantics and stable labels; pointer, Enter/
Space, arrow navigation, Home/End, Escape and focus restoration work.
One menu at a time; outside dismissal performs no action. Menu opening is not a
file operation and must not commit/discard a pending title/Markdown/inline draft.
Actions retain normal existing writable/modal/IME/async/session guards.
Menus must not stack over active dialogs or bypass replacement confirmation.
File chooser-triggering actions retain real user activation (not deferred
synthetic timers or direct storage injection).

Update Help anchors/reveal behavior and About/manual guidance for actions now
inside menus; a hidden target cannot be highlighted as if visible.
Opening Help/Settings/About from a menu closes that menu and later returns focus
to the correct menu trigger. Preserve Present's existing chrome/exit semantics,
history, camera, selected objects, drafts and explicit library/sidebar intent.

Menus, dialogs and remaining top action controls must be fully usable at
1440x900, 390x844 and 720x450 in both themes without clipping/overlap/page-width
overflow. Avoid new dependencies or a broad styling rewrite.
