# DGM-135: MCP Diagram Snapshot And Exports

Date: 2026-10-28. Status: COMPLETE / INDEPENDENT SOURCE ACCEPTANCE PASS.
Authority: PO requested "make the mcp snapshot the diagram and also export
through the mcp (agent can use the app to make diagrams)" and selected
"PNG snapshot + SVG, PNG and JSON exports (Recommended)".

## Context And Public Contract

Extend DGM-131's existing authenticated loopback MCP with two additive read-only
tools, published with exact schemas by tools/list:

- `snapshot_diagram`: required current `stateToken`, no other arguments.
  Return a PNG of the entire committed diagram, using normal export rendering,
  at scale 1, diagram background, content bounds and the normal export-grid
  setting. This is the diagram, not a desktop screenshot, selection, draft,
  temporary presentation ink or UI chrome.
- `export_diagram`: required `stateToken` and `format` (`svg`, `png`, `json`,
  `markdown`). Markdown returns the single `.md` with inline PNG and description
  specified in DGM-136, as a UTF-8 text/markdown embedded resource.
  SVG/PNG accept the existing image export options: optional `scale` (1 or 2),
  `transparent`, `background` (`diagram` or `white`), `aspect` (`content` or
  `16:9`) and `includeGrid`. Defaults match the app's normal export behavior.
  No selection or path arguments. JSON returns the normal native editable
  document, not a skill-import schema, and rejects image-only options.
  SVG/PNG/JSON additionally accept optional `includeMarkdown` (default
  false). When true, use DGM-136's shared helper to return one ZIP resource
  containing the chosen diagram export plus its companion description `.md`.
  The ZIP uses standard embedded resource blob content (base64,
  application/zip), an inert owned URI and matching filename/length/token
  metadata. Reject includeMarkdown true for markdown format. Markdown supports
  the PNG image options. Snapshot stays a plain PNG; no includeMarkdown option there.

Return bytes directly through MCP, not downloads/save dialogs, clipboard,
server filesystem paths, external URLs or arbitrary file access.
Snapshot/PNG includes standard MCP image content (`type: image`,
`mimeType: image/png`, base64 data). SVG/JSON use standard embedded resource
content with MIME type and UTF-8 text and an inert application-owned URI; no
resource-reading endpoint is implied. Include a text metadata content block
with matching stateToken, MIME type, suggested safe filename and byte length.
Freeze exact metadata shape and response schemas in implementation docs.

Capture one validated canonical document and token at request start and recheck
token and request activity after async rendering. Reject stale or changed state,
expired/disconnected requests, unloaded/reloading renderer, unfinished editor
interaction/draft/modal, or conflicting async work with explicit tool errors.
Recovery/unavailable errors must not return an old cached image. Reads may work
in a settled read-only ownership state; never mutate to make rendering succeed.
No document/history/autosave/selection/camera/theme/preferences changes.

## Implementation Boundaries

Reuse normal SVG/PNG/font/icon/export bounds and native JSON serialization.
Use narrow typed correlated main/preload/renderer requests, either extending
existing broker machinery with discriminated request/result contracts or a
small shared broker where needed. Do not fork rendering or a document model.
Validate tool arguments and all IPC boundaries/results; authenticate existing
registered live main frame only. Preserve existing token/Host/Origin/media/body/
concurrency/rate/time limits, sandbox/CSP/navigation/permissions policies.
Do not add dependencies, arbitrary IPC, filesystem APIs or external fetches.

Set and document a bounded export response size, at most 8 MiB serialized bridge
response, and explicit error when exceeded. Reject oversize bytes before base64
where possible. Existing renderer pixel/dimension caps still apply. Do not
raise global limits or deadlines. In-flight work cancels on reload/shutdown/
disconnect and cannot complete into another renderer generation. Unknown
options/formats, JSON image options, invalid tokens and malformed renderer
results are errors, never success-shaped fallbacks.

## Acceptance And Tests

- Given advertised tools, actual authenticated HTTP calls return decodable PNG,
  valid SVG and   parseable native JSON with accurate metadata/current token. includeMarkdown
  returns independently decodable two-member ZIPs with exact same-state image
  or JSON and UTF-8 description, not additional downloads or filesystem paths.
- Given a diagram built/edited through existing MCP, snapshot/export reflects
  those exact committed edits and normal rendering/JSON output. An agent can
  create, arrange, inspect PNG, edit, then export without manual UI interaction.
- Given invalid/stale/changed tokens, malformed input/output, drafts/modals,
  reload/unavailable, abort/timeout or excessive output, reject explicitly and
  preserve document/history/selection/camera/preferences with no late result.
- Given PNG/SVG options, existing background/transparency/aspect/grid/scale
  behavior and image/font/icon bounds are preserved. JSON roundtrips through
  normal Open JSON validation; no image options silently ignored.
- Existing mutation/discovery/transport/security tests remain green; add RED/
  GREEN server/schema/IPC/session/bridge tests, typecheck/build, and independent
  actual source-Electron HTTP acceptance for create -> inspect -> edit -> export.
