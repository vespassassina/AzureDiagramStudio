## Context And PO Decision

PO request: "if i drag a box out of a boundary, make the box/item move out of
the boundary. if i move a box/item inside a boundary (must be inside) make it
become part of the boundary. if i move it on the border, the boundary changes
size to include the item. only fully in/out changes the boundary contents.

today if i try to move out it increases the size of the boundary box.

make boudaries resizable"

Clarification: "make boudaries resizable hand resizable (juat dragging the borders".

The PO selected "Expand only its current parent; join another boundary only
when fully inside (Recommended)". The clarification explained membership is
decided on release, so a parent cannot keep expanding during a drag and trap
the item. This is source-only; no new persisted fields, external MCP schema,
dependency, package, installation or Git delivery is authorized.

## Current Root Cause

Existing move commands expand ancestors immediately. The editor previews the
same command for every pointer move, so the boundary grows as the child escapes.
Parent changes currently require the explicit Parent property.
Boundaries already expose selected NodeResizer controls, but that is not direct
border grabbing. The resize command currently changes width/height only;
left/top border movement needs an atomic origin/child-local compensation path,
not two independent move/resize commits or ignored origin changes.

## Drag Membership Contract

1. Capture the canonical pre-gesture document, absolute item rectangles and
   original boundary rectangles. Preview motion without committing membership
   or incrementally expanding its parent. At release, classify against the
   captured bounds, not a parent already grown by preview.
2. A root/unparented item joins a boundary only when its whole rectangle is
   inside. Mere overlap or border contact does not adopt it or expand a
   foreign boundary. A member fully outside its old parent leaves it; an old
   parent must not expand to recapture it. If now fully inside an eligible
   other/ancestor boundary, reparent there; otherwise use the canvas.
3. If an item remains partially across/touching its current parent border,
   keep membership and expand only that existing parent enough to include it.
   Existing padding/header readability stays. Do not shrink the old parent
   automatically when an item leaves.
4. Prefer the innermost eligible fully containing boundary; retain a current
   fully containing parent rather than arbitrarily switching to an overlapping
   peer. Do not choose the item itself/descendants or exceed existing nesting
   limits. Preserve nested ancestry and reject cycles. Freeze deterministic
   overlap/tie behavior in tests before editing; escalate any required change
   to these rules rather than inventing a different membership policy.
5. Reparenting preserves the dragged item's absolute drop location. Growing or
   shifting a boundary preserves all other children's absolute positions.
   Dragged selection roots move together; descendants of a selected boundary
   are not independently reparented. No cross-page/workbook movement.
6. Geometry, membership and necessary ancestor growth commit atomically as one
   undoable gesture/revision. No-op, return-to-origin or cancellation has zero
   edit history. Escape, cancellation, stale document/ownership and ignored late
   releases preserve original state. Keep snap, pan/zoom and connection route
   invalidation consistent with existing geometry changes.

Use a narrowly scoped internal drop operation if necessary, not a silent
change to all programmatic move/layout/alignment commands. Preserve explicit
Parent property and existing CLI/MCP command contracts.

## Direct Border Resize Contract

- In Edit, grab any boundary edge or corner directly, without opening Properties
  or first finding a tiny selected-node handle. Show predictable resize cursors
  and real hit regions at practical zoom. Keep boundary movement on its header/
  other established move surface; do not make one drag both move and resize.
- Resize all four sides and corners. Moving left/top updates the boundary
  origin and compensates child-local positions so contained items stay fixed
  in absolute canvas space. The opposite edge stays anchored.
- Clamp at contained content, header and minimum dimensions. Resizing does not
  move/scale children, adopt unrelated nearby items, silently detach members,
  clip text/content or remove children. Current membership changes only from
  item-drop rules, not from boundary resizing.
- Parent nesting constraints still hold; grow an existing ancestor only where
  necessary under the established geometry policy, preserving other content.
- One preview transaction and one commit per drag, with no-op/cancel/Undo/Redo,
  pointer capture and late-release guards. Accessible keyboard alternatives
  and focus indication remain available. No edit in Present/read-only/blocked
  modal modes; preserve existing node gesture mode-entry policy.
- Edge hit layers must not steal component dragging, boundary connection
  handles, text editing, context menus or underlying pan/selection behavior.
