## Proposed Contract

Swatches: Light grey, Medium grey, Dark grey, White, Black, Red, Green, Yellow,
Blue, Orange, Purple, Brown. Reuse matching incumbent standard-color values;
freeze any missing grey/brown constants in tests before implementation.
Give every swatch a readable accessible name, visible selection state and
contrast outline; white/black choices remain discernible in both themes.

Store an optional explicit grid color with diagram settings. Absence means the
existing automatic contrast-aware color, not a forced new default. Provide
Automatic/reset to clear an explicit choice. Color picking must not change
grid visible/style/spacing/snap/present/export or force a hidden grid on.
No RGB mixer/custom-color UI is requested in this task.

Explicit color remains the selected color across light/dark theme, backgrounds,
page switching and reload; do not silently replace it with a contrast-derived
hue. A deliberately white grid on white may be invisible, but swatch selection
and Automatic must remain accessible. Dots and lines use the same setting.

Use the shared grid/render path for editor, Present when enabled, and actual
SVG/PNG/PDF/Markdown/ZIP/headless output when includeGrid is enabled.
Export grid off stays off. For a format unable to represent the requested grid,
report/document the limitation rather than silently claiming fidelity.
UI, validation, serialized JSON and CLI/MCP metadata must agree.

One accepted choice is one normal Undo step, redundant selection no-op.
Respect read-only/Present/modal/typing guards. No global preference migration.
