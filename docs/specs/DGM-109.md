## Context and Existing Contracts

Read [lessons](../lessons.md), [DGM-100](DGM-100.md), [DGM-111](DGM-111.md) and
[nearby DGM-108](DGM-108.md). Source observations are from the current dirty tree,
not proof of native-platform qualification or human starter usability.

- [Session](../../app/src/app/session.ts) exposes `newDocument()`,
  `openFile(file, 'open' | 'import')`, `saveJson()`, `command()`, `presentation()`
  and `canMutate()`. `newDocument()` uses `createDocument(newId())`, existing
  backup-dirty `confirmReplace()` and `replace(document, true)` for Blank.
- `openFile` checks .json and 5 MiB, validates native input with `parseDocument`
  or maps skill input with `importSkillSpec`, layouts only skill Import and
  confirms after validation/layout. Native Open marks content backed up;
  Import does not. Request/generation checks reject superseded work, including
  commands, previews, newer file choices, Present and lost ownership.
- Internal `replace` invalidates pending layout/file requests, increments the
  generation, clears preview and past/future history, replaces the canonical
  document and schedules local autosave. It provides no retained old-document
  recovery archive. Accepting confirmation can discard unexported changed work.
- [Browser confirmation](../../app/src/app/browser.ts) warns that autosave is
  not a JSON file backup. Decline must keep the replacement-entry document and
  history. Preserve this protection; no silent replacement or extra retention.
- [App callbacks and pickers](../../app/src/App.tsx) and
  [EditorProps](../../app/src/contracts.ts) currently use `onNew`, `onOpen`,
  `onImport`, `onSaveJson`; there is no starter replacement callback.
- [EditorSurface](../../app/src/editor/EditorSurface.tsx) has `New diagram`,
  `Open JSON`, `Import skill JSON`, `Save JSON`, `Present` and
  `Exit presentation` identifiers. `fileAction` finishes a valid draft before
  invoking file actions. Opening a non-mutating chooser must not use that
  mutating finalization step; choosing a replacement must honor it.
- Editor selection is session-only. On a new document ID, existing effects reset
  tool/connection source/measurements/notice, but filter selection by object IDs;
  identical IDs in two starter copies can survive that filter. Do not claim
  that fresh document identity alone clears selection. A successful starter
  replacement needs explicit selection/draft cleanup, not a global Open policy
  change. Declined/canceled choices retain the current selection and camera.
- Present and read-only are independent mutation guards. Entry invalidates
  pending replacements; exit cannot restore a lost lock. Chooser callbacks
  must use the owning session guard, not only disabled buttons.

## Proposed Chooser and Replacement Integration

Use the existing `New diagram` entry for a compact optional chooser containing
Blank and the four examples, not a landing page. Opening, navigating and closing
the chooser change only ephemeral chooser/focus state; they do not finish drafts,
change document/history/backup, schedule autosave, run layout or clear selection.
Escape/close returns focus to the origin. All choices are keyboard/pointer
reachable with truthful preview/title/synthetic information. No marketing copy.

Only explicit choice invokes the existing draft-validation/finalization behavior.
An invalid draft blocks the choice with its existing error. A valid draft may
commit before replacement confirmation, as current file actions do. Capture
cancellation invariants at replacement entry after that finalization; do not
promise that declining replacement rolls back a legitimate draft commit.
Chooser cancellation before choosing remains strictly non-mutating.

Approved session boundary, to be implemented by this task:

- Keep Blank on `onNew` / `newDocument()` and its present backup-marker behavior.
- For the four examples, propose `openStarter(key): boolean` on the session and
  `onChooseStarter(key): boolean` on EditorProps, with a fixed four-key union
  `web-api | event-driven | fabric | enterprise`. The boolean reports accepted
  synchronous replacement, not file-save success. Reject unknown keys safely.
  App would wire it explicitly; no new DocumentCommand or schema field.
- Before any replacement, recheck `canMutate()`, validate bundled data, allocate
  and validate a fresh `dependencies.newId()`, then use existing backup-dirty
  confirmation and recheck the guard. Decline/error returns false and preserves
  replacement-entry document/history/backup. Accepted starter replacement uses
  internal `replace(candidate, false)`: a bundled example is not a user's editable
  JSON backup. Accepted Blank retains `replace(blank, true)` unchanged.
- Successful choice discards old history under the current replacement contract,
  cancels pending requests/layout, clears stale preview/inline/connected-picker
  state and entity/edge selection, resets connection source/tool as established,
  and schedules autosave once. No extra post-replacement layout or geometry change.
  A rejected choice does not clear selection or publish a fake successful start.
- For Blank, observe actual document identity after the existing callback before
  closing/resetting UI; a void callback alone is not an acceptance signal. Guard
  repeated activation to avoid duplicate replacement, confirmation or autosave.
- Ownership loss, Present entry or another document replacement closes/disables
  the ephemeral chooser and makes stored callbacks harmless. Older Open/Import
  reads/layout results cannot later overwrite an accepted starter. Preserve
  existing Open/Import/Save JSON callbacks, names and read-only export behavior.

Do not fake an OS file to call native Open: it marks a bundled starter as backed
up. Do not route native examples through skill Import or auto-arrange them.
Callback/signature, backup policy, entry and cancellation semantics are frozen by
the approval above. A different integration must be escalated to Orchestrator/PO;
implementers do not invent the interface or broaden existing callbacks.
