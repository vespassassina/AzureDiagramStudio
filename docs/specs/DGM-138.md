# DGM-138: Saved Workspace Root And Default File Locations

Date: 2026-10-28. Status: COMPLETE / INDEPENDENT SOURCE ACCEPTANCE PASS.
Authority: PO requested "in the settings allow saving the root folder for the
workspaces and new stuff. default is Documents/AzureDiagramStudio/" and chose
"Yes-use it for new workspaces and default save/export locations; leave
existing data untouched (Recommended)".

## Context And Contract

Add a Workspace root section to desktop Settings showing the resolved absolute
root, Choose folder and Reset to default actions, explicit persistence/error
feedback and the scope of the setting. Default is
`path.join(app.getPath('documents'), 'AzureDiagramStudio')`, respecting Windows
redirected/localized Documents rather than hard-coding the user home.
Persist the choice in this app profile across restarts without moving existing
work, recovery data, old files or profiles.

Use the chosen root for new per-document workspace folders and as the default
destination of Save JSON and all UI diagram/ZIP/Markdown exports. Materialize
workspace folders lazily on first actual save/export, not by opening Settings
or canceling New. Use a safe stable per-document subfolder identity so same-title
documents cannot share a workspace accidentally and title edits do not scatter
one workspace across directories. Document/freeze the mapping in the report.
Root changes affect subsequent destinations; old directories remain untouched.

Keep a normal native save dialog so the user can choose another destination;
do not silently overwrite files or force downloads into the root. Normal
browser-only builds retain browser downloads and explain that desktop workspace
root configuration is unavailable. MCP outputs remain returned bytes, not
automatic filesystem writes, even when a workspace root is configured.

## Boundaries And Safety

Use fixed typed preload operations for reading settings, invoking a native
directory chooser, resetting the root, and preparing a bounded validated
document-export default destination if needed. No generic filesystem/path
execution API, arbitrary renderer file reads/writes, or path supplied by MCP.
Validate registered live-main-frame sender, IDs, safe filenames, byte/argument
bounds and cancellation. Main owns path resolution and settings persistence.
Preserve all existing sandbox/CSP/navigation/permissions policies.
Do not grant OS/cloud permissions or change external client configuration.

Only explicit Choose/Reset changes the stored preference. Cancel leaves it
unchanged. Validate selected directory usability without destructive probes;
filesystem/persistence failures are visible and do not claim a saved setting.
Use atomic preferences writes and handle corrupt/unreadable settings explicitly.
Do not silently fallback to another folder after a chosen root becomes
unavailable; report the save/preparation failure and let the user choose.
Do not write external default Documents files during tests: inject owned
temporary directories/native-dialog adapters and retain evidence.

## Acceptance And Tests

- Given fresh desktop profile, Settings displays the OS Documents-based default;
  reopening/restarting preserves chosen custom root and explicit reset.
- Given directory chooser canceled or setting persistence failure, previous

  destinations stay distinct/stable and are under the configured root.

- Given missing/unwritable root, unsafe filename/ID/untrusted IPC, reject without
  arbitrary writes, silent success or automatic fallback.
- Given browser-only Settings/downloads, show honest desktop limitation and
  preserve normal browser behavior. MCP returns in-memory output as before.
