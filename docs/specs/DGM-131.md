# DGM-131: Always-On Local Desktop MCP And Settings Address

Date: 2026-10-27. Status: COMPLETE / INDEPENDENT SOURCE ACCEPTANCE PASS.

the app. that is always on by default. a button in settings to get the address."
The PO explicitly directed autonomous implementation. This replaces the earlier

## Context And Scope

Add a local MCP endpoint to the Electron app, running automatically for the
lifetime of its owned desktop instance. Add accessible Settings with running/
unavailable/error status and a Copy MCP address button. This is not an OS
service and stops on app exit. Browser-only builds must say desktop is required,
not start an unauthenticated development server.

Required discovery tools are `get_document`, `search_catalog`, `list_templates`
and `get_app_info`. Return the current committed session document, not a stale
disk backup or unfinished draft. Required mutation tools create a blank/template
diagram and edit the current diagram using canonical document commands.
Support adding/editing/removing components, text, rectangles and boundaries,
connections, metadata/Markdown descriptions, movement/resizing/grouping/
reparenting/order. Support the existing Auto-arrange operation and Undo/Redo
through narrow tools. Do not accept client-computed `applyLayout` as a substitute
for the real layout worker. Tool names/argument schemas are documented when
frozen by implementation; no claimed capabilities beyond implemented tools.

All modifications flow through the live renderer's session/domain validation,
history and normal autosave pipeline, not direct storage/file changes or a
second document model in main. One atomic edit batch is one Undo step: validate
the entire bounded batch before committing, and reject it wholly on failure.
No arbitrary file access, shell execution, OS input automation, external-client
configuration changes or released-package mutation is part of this feature.

### Write Concurrency And Interaction Contract

Reads return an opaque current-state/version token in addition to the native
document. Every mutation requires that token and checks it against the live
session immediately before committing. It must change across edits, replacement,
reload, Undo and Redo; document ID/revision alone must not permit ABA stale writes.
Return the updated token/document on success and a meaningful tool error on
stale, invalid, unavailable, read-only or interaction-busy requests.

Reject writes during recovery, ownership loss, Present, active drafts/IME,
gesture/preview, modal or other conflicting async operation. Never blur, commit
or discard a user's draft to execute MCP work, never bypass existing replace
confirmation, and never return success after a session's silent command refusal.
Creating a blank/template uses normal validated replacement semantics, including
the existing unsaved-work confirmation when needed. Cancel is an explicit tool
failure with unchanged state. Successful New retains the UI's reset-history
semantics; ordinary edits retain one-step Undo and normal user-visible autosave.

Serialize mutation dispatch and correlate responses to the registered renderer
and its generation; bounded timeouts/reload/disconnect reject pending requests.
Do not let expired/timed-out requests mutate later. Long-running layout must
recheck the live token/ownership/interaction guard before commit and use existing
stale-layout cancellation semantics. No write when the renderer is absent.

## Transport And Security Contract

- Implement the minimal stateless MCP Streamable HTTP JSON response transport
  using existing Node capabilities; no new dependencies. Support the documented
  initialize/initialized/ping/tools-list/tools-call flows and protocol version
  negotiation. GET may return 405 because server push/SSE is not offered.
  Do not advertise capabilities not implemented.
- Bind only `127.0.0.1`. Prefer a named constant port, fall back to an OS-assigned
  loopback port if occupied, and display the actual address. Never bind all
  interfaces, forward ports or silently expose remote access.
- Require a random per-app-launch bearer token on every HTTP request. Settings
  has an explicit Copy access token action and explains that it changes after
  restart. Never put tokens in URLs, logs, telemetry or committed files.
  Copy address does not silently copy credentials.
- Reject untrusted Host/Origin, cross-origin browser/preflight traffic,
  unsupported media types/versions, malformed JSON-RPC, unsupported methods/
  tools/arguments, oversized bodies and excessive in-flight work. Bound request
  and shutdown time. No CORS wildcard, arbitrary URL fetching or filesystem API.
  Clear snapshot state on reload/unload; do not serve stale work after failure.
- Preserve existing CSP, request/navigation/permission denial, sandbox,
  contextIsolation and nodeIntegration policies. A minimal sandbox-compatible
  preload may expose narrowly typed status/copy/snapshot and correlated
  mutation-request/response functions only; validate
  every IPC sender as the registered live main frame at the trusted app origin.
  No generic ipcRenderer, clipboard text setter, filesystem or Node exposure.
- Publish committed document/catalog/template snapshots through that bridge;
  validate shape/size at the boundary, bound data and return unavailable errors
  before recovery or after renderer destruction. Do not copy secret tokens into
  the renderer except on explicit user request to copy through the main process.
- Start/stop errors are structured and visible in Settings; do not crash or
  silently claim the server is running if listen/bridge/snapshot fails.

## UI And Client Setup

Settings is available beside informational rail controls and via Commands if
appropriate to existing patterns. Reuse informational modal guards so opening/
closing preserves drafts, document, Undo, selection/camera/panel state and
blocks background shortcuts/pointer actions. Escape/Close return focus, Tab is
contained, controls remain reachable at 390x844 and 720x450 in both themes.

Settings shows actual address and read/write access scope, Copy MCP address and
Copy access token, explicit success/failure feedback, restart/token lifetime and
same-machine-only guidance. The token is not displayed in plain UI text.
Browser builds show an honest desktop-only unavailable state.

Document manual HTTP endpoint + Authorization header setup for Claude Code and
VS Code/GitHub Copilot where documented. No external configs are modified here;
Scout and other unspecified client variants remain generic MCP client guidance,
not claimed tested integrations. Require actual client tool calls before calling
client-specific compatibility verified.

## Implemented Contract And Retained Owner Evidence

The implemented discovery tools are `get_document`, `search_catalog`,
`list_templates`, `get_app_info`; mutations are `create_diagram`, `edit_diagram`,
`arrange_diagram`, `undo`, `redo`. `get_document` and successful mutations return
JSON text containing `{document, stateToken}`. All writes require that token.
`edit_diagram` accepts 1-100 canonical commands, excluding client `applyLayout`.
`create_diagram` accepts an optional existing template key; omitted means blank.
`arrange_diagram` accepts `RIGHT` or `DOWN`. Complete schemas are published by
`tools/list` from `app/electron/mcp-schema.mjs`.

The preferred endpoint is `http://127.0.0.1:37431/mcp`, with an actual ephemeral
fallback on port conflict. Transport versions are `2025-06-18` and `2025-03-26`.
Limits are 64 KiB HTTP bodies, eight concurrent HTTP requests, 32 connections,
five-second HTTP and four-second correlated mutation timeouts, an 8 MiB bridge
payload bound and the existing 5 MiB native-document limit.

`final/source-inputs.json`. Final owner evidence records 69/69 desktop checks,
