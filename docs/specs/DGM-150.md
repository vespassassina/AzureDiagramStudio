## Context

The PO requested headless direct CLI commands and CLI-launched MCP for other
local AI tools/agents, guide coverage and the lowest possible usage resistance.
Use safe defaults and one entry point; no manual token copying, browser/runtime
download, visible editor, global setup or required background service.

The PO selected "Approve the low-friction CLI and stdio MCP interface
(Recommended)" after the scoped file/stdio/worker/guide approval question.
The RFD and this source-only contract are implementation authority; broader
security policy changes, dependencies and packaging remain unapproved.

## Approved Contract

Entrypoint notation below is `ads`; it denotes the existing app executable or
the documented source runner, not an installed alias or PATH change.

| Invocation | Result |
| --- | --- |
| `ads --help`, `ads <command> --help`, `ads --version` | Discoverable usage/version without UI or server |
| `ads new [--template KEY] [--out FILE]` | Valid blank/template JSON, stdout when no output path |
| `ads validate FILE` | Validated native diagram result or structured input errors |
| `ads inspect FILE` | Valid current native diagram and useful summary |
| `ads edit FILE --commands COMMANDS_FILE [--out FILE]` | Atomic validated existing command batch; stdout by default |
| `ads arrange FILE [--direction RIGHT|DOWN] [--arrangement standard|stacked] [--out FILE]` | Real shared layout, existing direction by default |
| `ads export FILE --format svg|png|json|markdown --out FILE` | Shared rendering, native editable output or embedded Markdown |
| `ads catalog [QUERY]`, `ads templates` | Discover component/template identities |
| `ads mcp [--input FILE]` | Stdio MCP, empty in-memory diagram by default |

`FILE`/`COMMANDS_FILE` may use `-` for stdin where unambiguous. Document exact
supported flags in generated help. No output file overwrite without explicit
`--overwrite`; no silent in-place edit. Use atomic output writes and preserve
the previous file on failure. Honor existing validation and output bounds.
Unrequested image options default to current scene behavior.

Normal command results are JSON; binary/artwork goes to the explicit output.
Stdout in MCP mode contains only newline-delimited JSON-RPC, never logs/banners.
CLI exit codes:0 success,2 usage,3 invalid input,4 file IO,5 runtime/render,
6 state conflict. MCP protocol/tool errors follow existing MCP conventions.

## Acceptance Criteria And Tests

1. True unattended operation: no visible window, dialogs, confirmation prompts,
   clipboard access or GUI profile startup. CLI and GUI can coexist without
   reading/writing GUI recovery, recent history, preferences or launch token.
2. Help/version, invalid flags and invalid inputs have deterministic stdout,
   stderr and exit status. Missing/oversized/non-JSON/invalid diagram and invalid
   command batch leave all inputs and outputs intact. Batch mutation is atomic.
3. Shared document validation, catalog, templates, command application, layout,
   scene/assets/fonts and PNG/SVG/Markdown behavior are reused, not approximated.
   Actual output dimensions, backgrounds and bytes/content are checked.
4. CLI file access is limited to explicit arguments. Output creation is atomic;
   overwrite is opt-in. The MCP host cannot accept arbitrary filesystem paths
   through tools; only startup `--input` reads a file.
5. Stdio initialize, tools/list, get_document, catalog/templates, create/edit,
   arrange, Undo/Redo, snapshot/export succeed with current state tokens. Stale
   tokens, malformed/oversized messages, concurrency and worker failure return
   explicit bounded errors without partial edits or stdout pollution.
6. EOF, interrupt, timeout and worker crash retire work and close owned resources.
   No listener, hidden worker or process is left running. Never weaken the
   existing sandbox/local request/origin/trusted-frame rules or GUI HTTP auth.
7. The manual and in-app guide explain Recent originals and headless workflows,
   exact source entrypoint, copyable CLI/MCP setup, stdout/file semantics and
   errors. Do not imply installed0.5.1 already contains either feature.

Write and execute failing tests before production edits. Retain RED/GREEN,
source/build provenance and first failures under `app/test-results/dgm150`.
Independent verification must include real Electron/subprocess CLI and stdio
MCP traffic, actual rendered outputs, ownership isolation and unchanged HTTP
tests; mock-only tests do not establish headless or Windows stdio behavior.
Packaging/portable launch remains a separate future gate, not certified by
source runtime checks.
