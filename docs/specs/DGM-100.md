## Task Cards

### DGM-101 - Predictable Object Order

Context: confirmed legacy normalization defect F1; new controls currently lack complete behavioral coverage.

Contract proposal: document commands, canvas and SVG use one effective order policy. Define sibling/group ordering so children remain visible above their own container; group movement in the stack preserves descendants' relative order. Define connection placement explicitly. Legacy documents retain their appearance until an actual order change. Both legacy layer commands and numeric order imports need specified behavior. Orchestrator/PO freeze this cross-module contract before code.

Cases: Given the F1 fixture, when the already-bottom object is sent to bottom, then every object's relative paint order is unchanged. Given contiguous/noncontiguous selections, when forward/backward/top/bottom runs, then selected and unselected internal ordering is stable. Given nested/overlapping containers, when selected/deselected, exported and reopened, then accepted stacking remains consistent. Given any change, one undo restores the original state and geometry/routes do not change merely because stacking changed.

Done: confirmed red regression first, four actions covered at domain/UI/export layers, distinct Lucide affordances/tooltips, legacy JSON round trip and independent browser confirmation. Excludes layer-management panel, visibility toggles and schema migration. Risks: React Flow automatic elevation, tie handling, parent precedence and old-client compatibility.

### DGM-102 - Stable Content-Sized Arrangement

Context: ordinary sample is stable across four layouts, but supported long headers produce excessive empty space.

Interfaces: retain `computeLayout`/revision application, `entityTextGeometry`, annotation absolute-position contract and one-step history. Do not substitute visual shrinkage that detaches routes or clips children.

Cases: Given compact and deliberately oversized versions of the same fixture, when arranged, then obsolete boundary dimensions do not dictate the result. Given 120/200-character headers, children, nested boundaries and boundary endpoints, then measured text/children fit and header padding uses actual required wrapping. For an isolated single-child boundary without routing constraints, target a first-child gap of 18-32 units after the rendered text bottom. Given ten same-direction arrangements, then geometry after the first is stable within 1 unit; test RIGHT and DOWN, plus RIGHT-DOWN-RIGHT. Given child removal, when arranged, unused bounds shrink. Annotations retain absolute positions and stale results remain rejected.

Done: failing compactness/repetition tests, compute/apply/browser checks and exported-fixture inspection. Excludes pinning, partial ELK layout, automatic layout during ordinary editing, or changing annotation membership. Risks: ELK compound sizing and route clearances; freeze feasible fixture-specific bounds before implementation rather than promising a global optimal layout.

### DGM-103 - Readable Workspace and Navigation

Context: controls consume roughly 40% of window width at 1280x720; mobile controls are small.

Interfaces: session-only panel/camera preferences; preserve document geometry and shared output. Retain IBM Plex Sans, compact chrome and semantic palette. Prefer one visible editor panel at a time by default where space is constrained; allow deliberate pinning. Keep the document title prominent without repeating it in a decorative inspector summary.

Cases: Given supported desktop/mobile widths and 200% browser zoom, no title/control overlap or horizontal page overflow occurs. Given no selection, unnecessary inspector space is reclaimed. Fit diagram and Fit selection respect visible chrome and do not move nodes. Touch-mode primary actions have at least 44x44 targets without forcing that density on desktop. Keyboard focus/descriptions remain visible; reduced-motion preferences are honored. Panels opening/closing do not unexpectedly jump the camera.

Done: deterministic viewport and focus tests, measured canvas occupancy, light/dark screenshots and contrast checks for normal text/non-text controls. Excludes a branding redesign or full mobile-first authoring. Risks: camera changes during gestures, tiny labels at fit-all scale; focus rather than pretending arbitrary large diagrams are all readable simultaneously.

### DGM-104 - Safe Presentation Mode

Context: customer/Teams screen sharing is a primary workflow, not an export-only afterthought.

Interfaces: presentation is session state, not portable diagram data. Reuse the current scene/camera. It is a mutation guard separate from storage's read-only-tab ownership; leaving Present must not regain write access if another session owns it. Optional fullscreen must gracefully fall back to in-window presentation.

Cases: Enter Present in one action after completing a valid draft or surfacing its validation error. Hide editing panels/grid/selection affordances, retain explicit status meaning, fit the current diagram or selection, and provide a temporary pointer. Delete/paste/drag/typing/file-drop/auto-arrange cannot mutate the document in Present. Pointer activity does not create history, autosave or export content. Escape/Exit restores camera, panel configuration, selection and focus; test browser fullscreen Escape behavior separately. A storage-lock transition still applies while presenting.

Done: snapshot/undo invariance tests, keyboard/touch exit, screenshot and actual Teams recipient check at 720p-equivalent view. Excludes live collaboration, presenter notes, animation timelines, saved slide decks and automatic redaction. Risks: metadata leakage in visible content; presenter must choose an appropriate diagram, and app fullscreen cannot suppress OS notifications or govern Teams window sharing.

### DGM-105 - Meeting and Slide Handoff

Context: current internal clipboard is not an image clipboard; export requires a file.

Interfaces: use shared SVG/PNG output and a narrow platform clipboard adapter; review browser permissions/Electron bridge security before implementation. Keep editable JSON distinct from images. Preview scope/crop before export, with full diagram and selection options, the saved diagram background from DGM-114, an optional white-background override, transparency and a 16:9 preset that never stretches the diagram. Grid remains excluded unless explicitly included under DGM-115. Coordinate these output contracts before implementing the handoff adapter; do not hard-code white as the only opaque background.

Cases: Copy image then paste into Teams chat and PowerPoint yields a clean image with intended text/icons, without grid/selection/pointer/chrome. Denied/unsupported clipboard offers PNG download and leaves the document unchanged. Selection export includes selected containers' contents and only applicable connectors; freeze this policy before dispatch. Oversized output retains the existing cap/error path. Exports include explicit status markers and only the chosen metadata scope.

Done: SVG/PNG parity, native clipboard permission/fallback tests and real Windows/Mac application paste evidence. Excludes native PPTX authoring, PDF, Visio/draw.io interchange or upload to Teams APIs. Risks: recipient clipboard format support, font rendering and inadvertent inclusion of off-scope customer content.

### DGM-106 - Find the Intended Service

Cases: APIM ranks API Management first; Entra ID ranks Microsoft Entra ID before Central substring matches; approved aliases such as AAD resolve to the current selectable product without resurfacing retired choices. Arrow/Enter/Escape navigation works; touch/pointer equivalents remain. Recent choices reflect successful insertions, not canceled placement or hover, and can be cleared. Exact label matches precede partial matches.

Done: deterministic alias/ranking fixtures, keyboard tests and timed search task. Excludes new icon sets, runtime network search and new search-engine dependencies. Risks: aliases can imply incorrect product equivalence; source and approve them editorially.

### DGM-107 - Add and Connect in Context

Interfaces: adjacent quick-add control opens the existing search picker; one domain transaction creates the node plus valid connector. Preserve boundaries, current direction, IDs and existing split-edge rules. Do not auto-reparent based on visual overlap; define an explicit sibling/container default.

Cases: Given a selected service, choose an adjacent service and commit once to place and connect it without moving unrelated entities. Cancel produces no change. One undo restores the complete prior graph. Keyboard and click-to-place work without drag. Selecting an edge exposes an explicit insert-on-edge action rather than an ambiguous palette side effect. Boundary depth/connection limits fail atomically.

Done: domain red/green tests, pointer/keyboard UI tests and M2 trial. Excludes AI suggestions, automatic graph generation and implicit global layout. Risks: insertion collisions and unclear parent ownership; collision preview must not become speculative auto-layout.

### DGM-108 - Direct Editing and Keyboard Actions

Context: small label changes require inspector travel; tool discovery depends heavily on hover.

Interfaces: inline editing reuses existing validation and draft/commit behavior. A compact searchable command menu dispatches the same actions as toolbar/context controls and honors read-only/Present states. Freeze shortcut conflicts for Windows/Mac before dispatch.

Cases: Double-click or keyboard action edits a selected label; Enter commits once and Escape cancels. Multiline notes retain newline behavior. Editing text never triggers canvas Delete/shortcuts. Commands can be found and invoked from the keyboard; unavailable actions are clearly disabled and focus returns to its origin. No command may bypass mutation guards.

Done: transaction/focus/accessibility tests and short timed rename task. Excludes rich text, typography panels and custom shortcut configuration. Risks: event bubbling, IME composition, browser/OS shortcut collisions; split inline editing and command-menu work if the estimate becomes L.

### DGM-110 - Local Alignment Tools

Context: users need a small spacing fix without rearranging the whole graph.

Mixed-parent operations either obey the approved absolute-coordinate contract or are clearly unavailable. One undo restores exact positions and attached connectors remain valid.

### DGM-111 - Clear Save and Transfer States

Context: Saved and JSON backup needed are both correct but easy to misunderstand during a meeting.

Interfaces: retain the current single active document, autosave, JSON and tab-lock model. Improve labels/actions without inventing cross-device sync. Prefer Saved on this device and a clearly separate Save a copy/export-file state; final copy is reviewed for desktop/browser accuracy.

Cases: Autosave success/failure is truthful; a successful editable-file export updates the backup reminder but a canceled export does not. New/Open/Import retain replacement protection. A user transfers JSON between browser and desktop and understands why their work is not automatically synced. Read-only users can still export. Manual matches actual supported controls and release/offline evidence.

Done: persistence/UI failure-state tests plus an uncoached transfer task and reconciled docs. Excludes automatic recovery-history retention, recent-document databases, cloud save and schema changes. Risks: privacy/data retention and platform differences in detecting successful file writes; escalate rather than implying guarantees.

### DGM-114 - Custom Diagram Background

Context: the PO requested a selectable background, not a white-only diagram. Sprint 2's light canvas was a readability default, not a permanent product restriction.

Proposed interfaces: a validated optional solid background color in the portable diagram, with white as the legacy fallback. Freeze its exact schema/metadata/scene contract before dispatch; do not migrate existing documents or introduce executable CSS. Use a compact color swatch/picker with an editable hex field and Reset to default in Document properties. Background is diagram appearance, independent of the light/dark editor theme. Persist and undo it through existing commands; preview changes during the picker gesture and commit once.

Editor, Present and opaque SVG/PNG use the same selected background. Transparent export omits the background fill without changing the saved setting. A white slide-background override is an explicit export option, not a document mutation. Readability rules adapt metadata, connector/annotation text and grid contrast to light/dark backgrounds without altering official icon bytes or saved object colors silently; surface any unresolved contrast warning rather than claiming arbitrary colors are all readable. Retain existing white component tiles unless a separate style change is approved.

Cases: Given an old document without background, appearance stays white. Given a valid custom color, preview/commit/undo, JSON open/save, autosave/reload and cross-device transfer retain it. Invalid color input leaves the last valid document intact. Given light, dark and saturated backgrounds, semantic labels and control focus remain usable in both editor themes and Present; export matches the selected background and contains no external assets. Transparent export has no background rectangle; optional white export does not overwrite the saved color. Background changes do not move nodes, reroute connections, trigger ELK or enter the Present session state. Read-only and Present guards prevent changes.

Done: focused validation/history and UI tests, exact background pixel/alpha checks in SVG/PNG, legacy/JSON/reload parity and light/dark/contrast browser evidence. Risks: old clients dropping optional fields, annotation/connection contrast, export transparency and raster antialiasing. Excludes gradients, uploaded background images, per-boundary wallpaper, changing official glyph colors and new color-picker dependencies. Current runtime remains unchanged until the task is separately approved for execution.

### DGM-115 - Grid and Snap Controls

Context: fixed editor dots currently use spacing 20 while snapping always uses 8. The PO requested grid and snap controls, not a permanently enabled invisible snapping rule.

Proposed interfaces: optional portable diagram settings for grid style, spacing, visibility and snap enabled, plus separate opt-in inclusion in Present and image exports. Freeze exact fields and absent-field compatibility before implementation. Controls: independent Show grid and Snap to grid toggles, Off/Dots/Lines style choices, and a bounded numeric spacing input with validation. Use one diagram-absolute origin and spacing for visible grid and snapping; propose 8 document units by default with a reviewed 4-128 range. With absent settings, preserve the existing snap-on behavior; aligning default visible dots with that spacing is an intentional visual refinement, not movement of existing objects.

Show grid off does not disable snapping; snap off does not hide the grid. With snapping off, pointer placement/movement is free rather than still rounded by insertion/drop helpers. Apply snapping consistently to component/annotation/boundary placement and dragging, and to supported resize handles without violating minimum sizes or clipping children. Convert nested parent-relative coordinates to absolute grid coordinates and back; selected parent/child movement remains single-counted. Freeze keyboard-nudge, duplicate and paste policies explicitly before dispatch rather than silently changing existing shortcuts or fragment-relative offsets. Grid controls never run Auto-arrange; existing layout is not forcibly quantized.

Present and exports hide the grid by default, independently of editor visibility. Users may explicitly include it for a technical drawing. Present ignores snapping because editing is blocked and cannot change the saved settings. Included grid uses the same origin/spacing across zoom, pan, crop and output scales, stays behind diagram objects, and remains distinguishable on the DGM-114 background. Transparent output omits only the background fill; an explicitly included grid remains transparent between its dots/lines.

Cases: Test all four Show grid/Snap combinations and both visible styles. Settings changes alone never move existing objects or alter history geometry/routes. With snap on, known pointer placements and drag results land on the shared absolute grid, including nested/multi-selection fixtures; with snap off, off-grid results retain their coordinates. Invalid spacing rejects cleanly. JSON/reload/undo preserve settings with legacy fallbacks. Fit/zoom/pan do not change grid alignment or document geometry. Grid stays out of default Present/SVG/PNG; explicit inclusion matches editor spacing/origin and remains below content. Output caps, background transparency, read-only and Present guards remain intact.

Done: deterministic coordinate/history tests, helper/UI snap tests, browser real-pointer nested placement/drag and visible-grid alignment, plus JSON and SVG/PNG inclusion checks. Risks: mixed parent coordinate spaces, helper rounding despite snap-off, resize limits, grid density at small zoom, contrast and output size. Reuse React Flow grid/background support and existing scene/export primitives; no new dependency. Excludes snap-to-object guides, automatic alignment, rotation, live layout and changes to group membership. Split editor controls and optional output rendering into sequential slices if needed for capacity; do not omit either requirement silently.
