# DGM-117: First-Use UI Guide

Date: 2026-10-16. Status: AUTOMATED COMPLETE / PARENT VISUAL REVIEW PASS.
Authority: PO requested a question-mark help button with ordered UI callouts
that explain and guide first-time use. This is a new, bounded source feature;
it does not authorize packaging, publication, signing or broader support.
Baseline: [current execution policy](../roadmap.md#current-execution-policy).

## Scope And Ownership

Add one accessible question-mark icon button to the existing editor chrome,
with a tooltip and an on-demand, replayable, ordered walkthrough. Reuse the
existing Lucide icons, theme tokens and modal/focus conventions. No automatic
popup, persistent preference, dependency, document/schema or public API change.

Implementer owns `app/src/editor/EditorSurface.tsx`,
`app/src/editor/Editor.test.tsx`, `app/src/editor/editor.css` and, if the
walkthrough is clearer as a separate component, `app/src/editor/HelpGuide.tsx`
and its colocated tests. Reuse existing test infrastructure. Orchestrator owns
this spec, roadmap and manual. Independent verifier owns evidence and report,
not production repairs. Shared-file and terminal work stay serial.

## Workflow And Contract

Ten steps in usage order: start a blank/starter diagram; name the document;
find/add components; move/select/navigate the canvas (including Undo);
connect components and add boundaries/text with the tool rail; edit properties;
auto-arrange; save/open editable JSON with honest local-save semantics;
export SVG/PNG; present and hand off. Each step names the actual control,
has a numbered progress indicator and a visible anchored highlight/callout.
Guide navigation never triggers the described document action.

Use Next, Back, Close/Escape and a final completion action; opening again starts
at step one. Show the real target by scrolling chrome or temporarily revealing
the relevant library/properties panel. Restore original panel intent on close.
Keep callouts within the viewport, including small/short screens, with no
overlap between the highlighted target and callout where space permits.
Resize/scroll must update the anchor; a missing target must not crash or strand
the dialog. Respect reduced motion. Match existing light/dark styles.

The walkthrough is an accessible modal with labelled content, sensible initial
focus, a Tab/Shift+Tab trap, live step announcements and focus returned to the
help button. Background editing/shortcuts must not execute while it is open.
Do not layer it over another modal or enter presentation from the walkthrough.
It remains available in read-only mode without enabling editing.

Opening, navigating and closing the guide must preserve document bytes,
selection, viewport, pending inline/inspector/title drafts and history. In
particular, focus movement must not accidentally commit or discard a draft.
No tutorial-created objects, network calls, telemetry or user data are needed.

## Acceptance Cases

1. Given the normal editor, the named Help button has a question-mark icon and
   tooltip; activating it opens step 1 of 10. It works with blank and populated
   documents and read-only mode.
2. Given the guide, Next/Back visit every step in the frozen order; Back is
   disabled at the beginning, the final action closes, and replay starts over.
3. Given any step, its target is visible/highlighted with a correctly positioned
   callout at desktop and mobile sizes, including library/properties steps and
   a viewport resize during the guide. Existing panel intent is restored.
4. Given keyboard-only input, focus stays inside the guide; Escape/Close/Finish
   return focus to Help. Delete, paste, Undo and tool shortcuts cannot mutate
   the background editor while the guide owns focus.
5. Given a pending title, property or inline label draft, opening and closing
   help neither commits nor cancels it. Selection, camera, document/history and
   draft are preserved. Guard composition and overlapping editor dialogs.
6. Given light/dark themes and reduced motion, guide content remains readable,
   controls reachable and text inside the viewport at desktop, mobile and a
   short landscape viewport. No horizontal page overflow or occluded actions.
