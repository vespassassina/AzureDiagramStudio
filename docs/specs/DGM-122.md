Date: 2026-10-17. Status: AUTOMATED SOURCE ACCEPTANCE COMPLETE / PARENT VISUAL REVIEW PASS.

## Contract And Scope

Add optional `Diagram.description?: string` and the corresponding metadata
patch field. It holds Markdown source up to 20,000 JavaScript characters,
preserving Unicode, whitespace, line endings and formatting literally.
Keep schemaVersion 1; documents without the optional field remain valid and
retain their original serialized shape. Empty/reset descriptions omit the field
when cleared through the UI. No migration or old-document rewrite is required.
Existing older clients may discard optional fields when resaving; document this
compatibility boundary rather than promising lossless editing in old binaries.

Extend native validation, metadata-command validation and reconstruction,
JSON parse/save, local storage/reload, Undo/Redo and session replacement paths
so the field is never silently dropped. Keep the 5 MiB whole-document bound.
Invalid non-string or over-limit values fail atomically; existing contracts for
all other fields and imported legacy documents remain unchanged.

In document Properties, add a labelled multiline "Architecture description
(Markdown)" field with a comfortable minimum height and responsive wrapping.
Follow existing draft/blur/commit/Escape/IME handling, one Undo per accepted
description edit, read-only/loading/Present/Help guards and error conventions.
Document-level Properties remain accessible when selecting objects via the
existing document-properties command; no per-component description is added.

No Markdown parser is currently installed. The PO was unavailable for the
dependency decision, so implement a Markdown SOURCE editor only: no new
dependency, hand-written Markdown parser, HTML injection, remote images or live
links embedded by rendering arbitrary description content. All text remains
inert. A rendered preview remains a separate explicit dependency/security choice.
The user request authorizes this additive saved-field contract, not a general
schema redesign, public service integration or data migration.

Description content is document metadata, not canvas artwork. Editing it must
not move/resize/recolor objects, rearrange route points or add long text to
SVG/PNG/Present. Keep existing routeRevision bookkeeping when the document
revision changes; do not weaken route-cache validation. Save JSON includes the
description; existing artwork exports stay unchanged.
Descriptions are not part of component-selection clipboard fragments.
