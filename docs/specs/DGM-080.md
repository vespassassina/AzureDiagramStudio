# DGM-080: Custom Images and Third-Party Vendor Icons

Date: 2026-10-09. Status: AUTHORIZED BY PO REQUEST AND DELEGATED ROUTINE DECISIONS.
Baseline: [V1](DGM-MVP.md), [release/publication](DGM-070.md), [lessons](../lessons.md).

## Context and Scope

The PO requests uploaded SVG/PNG/GIF/JPEG/etc. icons and common third-party company icons, including Oracle, SAP, IBM, AWS, Google Cloud and HP. Prior desktop/package verification and GitHub publication are still incomplete; do not claim an executable is tested offline or a repository is published until verified. The PO is unavailable and delegated routine choices when asked about SVG safety and vendor rights.

Choose safe embedded uploads: SVG, PNG, JPEG/JPG, GIF and WebP; BMP may be supported if native decoding is verified. SVGs use approved DOMPurify defense-in-depth and are rasterized to PNG. Animated inputs use their first frame. Built-in catalog SVGs remain vector/unchanged. This is explicitly documented, not silent loss of custom vector/animation semantics.

## Compatible Contract Extension

- Add optional `Entity.customIcon` with `{name:string,dataUrl:string,width:number,height:number}`. Name is <=120 characters, dataUrl is strictly normalized embedded PNG, width/height are positive integers <=512, matching IHDR. Encoded field <=384 KiB, bounded decoded byte count. Existing 5 MiB document/100-entity/150-edge caps remain. No arbitrary URLs or filesystem paths.
- Existing `icon` stays as a builtin fallback; a valid customIcon overrides only component artwork. Older documents without the field round-trip exactly; no storage migration/deletion. This optional schema-1 extension is authorized by the new feature request; pre-feature clients may discard it and are not custom-image-compatible.
- Extend EntityPatch to include customIcon; clearing it uses undefined. Builtin type selection clears an override. Domain validation, layout semantic guards, clipboard, undo/redo and snapshots preserve the complete image. A custom image replacement is one undoable transaction.
- Uploaded icons are document-local, embedded with their components rather than an external global library. Import with a selected component replaces its icon; otherwise create a component at a sensible canvas location. Copy/paste across a new document retains the embedded field. Downloaded JSON is the portable backup.
- Shared helper paths `app/src/custom-icons/contract.ts` (pure types/binary/data validation) and `app/src/custom-icons/import.ts` (browser import/normalization). Pure validation may be used by document and scene without importing DOMPurify/browser decoding into Node validators. Browser importer accepts a File, returns a normalized CustomIcon or actionable error; no document/store mutation.

## Security and Limits

Raw file limit 2 MiB; only verified supported image media; restrict source dimensions/pixels before expensive decoding where native header metadata permits. Normalize to a maximum 512px dimension, preserving aspect/transparency; if necessary downscale further to fit the encoded cap, otherwise reject clearly. No network fetch, embedded remote resources, file URLs or arbitrary HTML.

SVG is parsed as SVG/XML with strict preflight rejection of DTDs, processing instructions, scripts, foreignObject, events and remote resources; DOMPurify is an approved pinned runtime dependency for defense-in-depth. Rasterize only validated sanitized inert SVG. Do not insert uploaded markup through innerHTML into the editor. Reject malformed/unsafe files without replacing selected artwork or clearing current work. PNG-only persisted data must validate signature, dimensions, bounded bytes and structural safety; JSON cannot bypass file-import protections by supplying SVG/HTML data URLs.

Retain Electron's sandbox, no Node bridge, CSP and network denial. Do not relax desktop security for imports. Normal browser File input is used. Custom PNG uses a data URL inside an image element, not executable markup.

## Ownership and Sequence

1. Foundation/image-security implementer owns shared optional field/types, pure validator, DOMPurify importer, runtime dependency/lock, focused tests and document validation/command preservation. Freeze names/behavior before UI/render dispatch. No desktop harness or publication changes.
2. Render/vendor implementer owns scene/entity-artwork, render memo field checks coordinated with UI, vendor catalog/bundled assets/provenance and tests. UI owner consumes fixed vendor registry; no schema redesign.
3. UI implementer owns import file input/actions, previews/errors, custom override clear/replace, vendor browsing/search, current option and relevant editor tests. Keep atomic previews/history/read-only, current file behaviors and latest-handler caching.
4. Desktop implementer repairs actual packaged-runtime verification, then rebuilds ARM64/x64 binaries after all image/vendor changes. No unsafe test hooks in production, Node bridge or broad CSP exception.
5. Independent verifier reports pass/fail without fixing code. Orchestrator owns GitHub creation/push/release after source hygiene and actual runtime verification; do not upload broken/untested artifacts.

## Given/When/Then Acceptance

- Valid SVG/PNG/JPEG/GIF/WebP upload creates or replaces artwork; opacity/aspect is retained and GIF is a still. Unsupported/corrupt/unsafe/oversized inputs leave the document unchanged and show an actionable error.
- Custom artwork survives edit/undo, copy/paste, grouping, Auto-arrange, autosave/relaunch and exact JSON open/save. Builtin selection/clear restores built-in artwork with one undo step.
- JSON with HTML/SVG/remote URLs, invalid PNG headers/dimensions/oversized data or active markup is rejected before replacement. Existing malicious-input/route/security tests remain; no cap/threshold waivers.
- Actual SVG and PNG export contain and visibly render custom icons plus vendor artwork offline; no external resources or scripts. Desktop CSP remains effective.
- Vendor catalog includes all requested identities with honest badge/logo classification, useful aliases and search, no pretend redistribution permission or logos in product branding.
- Read-only sessions can browse/export but cannot upload/replace/delete images. Desktop/mobile controls fit and file-dialog cancellation changes nothing.
- Unit/typecheck/build and relevant real-browser workflows pass. Original 100-entity/150-edge latency/layout gates remain. Packaged offline verification includes image upload/open/export and confirms no remote request.
