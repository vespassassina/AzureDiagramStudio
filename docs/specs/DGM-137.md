# DGM-137: Diagram Sidebar Control And Auto-Arrange Menu

Date: 2026-10-28. Status: COMPLETE / STRICT-STACKING INDEPENDENT SOURCE PASS.
Authority: PO requested removal of Paste and Markdown buttons, a square sidebar
button after Auto Arrange at the edit area's top right, and an Auto-arrange
dropdown with horizontal, vertical and two layered options. PO clarified:
"Existing groups: horizontal contents with groups stacked vertically, or
vertical contents with groups side by side (Recommended)".

## UI Contract

Remove dedicated Paste buttons from the drawing rail and selection toolbar.
Keep existing copy/cut/paste keyboard shortcuts, context menu and Commands;
the request concerns buttons, not removal of editing capabilities.
Remove separate Open Markdown and Document properties rail buttons.

Place one square accessible "Sidebar" button immediately after Auto-arrange
at the top-right of the editing canvas, not in the application title bar.
It opens/closes the existing shared sidebar and exposes both existing
Properties and Markdown views through accessible tabs/choices in that sidebar.
Preserve shared draft state, resize/cancel/collapse/reopen behavior and guards.
Opening the control cannot silently commit/discard a Markdown/title draft.

Remove the two standalone direction buttons beside Auto-arrange. Make the
Auto-arrange button a dropdown with four clearly named choices:
Horizontal; Vertical; Horizontal groups stacked vertically; Vertical groups
side by side. Opening the menu does not arrange immediately. Choosing a mode
closes the menu and runs the existing explicit async layout flow once.
Provide aria-expanded/menu semantics, keyboard activation/navigation/Escape,
focus return and real pointer hit targets in desktop, 390x844 and 720x450,
both themes. Preserve read-only/Present/busy/IME/modal exclusion.

## Layout Contract

Horizontal and Vertical preserve existing RIGHT/DOWN behavior. For layered
modes, existing boundary membership defines layers, not graph dependency ranks:
horizontal contents within each boundary with top-level boundary units arranged
vertically; vertical contents within each boundary with top-level units arranged
horizontally. Use existing hierarchy at nested boundaries consistently.
Root ungrouped components participate as individual outer units; with no groups,
fall back to the respective normal horizontal/vertical layout. Preserve stable
document ordering as a deterministic tie breaker, never random coordinates.

Use the real ELK layout engine and existing measured sizes/header convergence.
Result must keep groups disjoint and children contained, route every existing
connection with correct endpoints/labels (including cross-group and explicit
ports), and preserve non-layout content, hierarchy and annotation absolute
positions according to existing invariants. No stale route after repositioning,
no merely changing direction metadata or hand-stacking without rerouting.
Retain worker cancellation, stale revision, one-Undo and normal autosave semantics.

Add a typed transient layout mode/options contract; preserve old RIGHT/DOWN
callers and saved JSON v1 without a schema migration. Wire UI/session/layout and
MCP arrange_diagram consistently. MCP keeps existing required direction and
adds optional arrangement enum (`standard`, `stacked`) mapping to the same mode:
RIGHT+stacked = horizontal contents/vertical stack, DOWN+stacked = vertical
contents/horizontal stack. Omitting arrangement preserves current behavior.
Keep existing mutation token/guards and strict argument validation.

  remain at old locations; Sidebar is square after the Auto-arrange dropdown.
- Given each menu choice via mouse/keyboard, invoke exactly one corresponding
  layout; menu opening/Escape alone has no diagram/history side effect.

- Given sidebar drafts and narrow/theme cells, properties/Markdown reachable
  through the one control with unchanged preservation and resize semantics.
- Existing MCP arrange callers still work; both stacked modes work through
  actual HTTP on the same live canonical diagram and return current tokens.

The PO reports that both grouped modes stagger groups, and horizontal contents
are not applied everywhere. The earlier order/orientation acceptance does not
establish the requested strict stacking and is insufficient for this behavior.
Preserve earlier passing evidence as bounded history, not current acceptance
of this defect.

identical left x coordinates and increasing disjoint y intervals in stable
order. For DOWN+stacked, they form one aligned row: identical top y coordinates
and increasing disjoint x intervals. Mixed group sizes, disconnected units,
cross-group/backward/cyclic connections must not introduce secondary-axis
stagger. Use a consistent measured gap. The requested contents direction must
be honored inside every nested boundary, not just selected roots. Test nested
sibling groups explicitly and state the actual shared-axis contract at each
relevant hierarchy.

This clarifies existing grouped-mode behavior, not a new layout mode or saved
schema. Real ELK routing, containment/header/port/label correctness, annotation
absolute position, standard-mode behavior, exact Undo and stale guards remain
mandatory. Reproduce the reported defect in failing geometry tests before the
repair; strengthen actual UI/HTTP acceptance to assert aligned shared axes and

verification must rerun the affected criteria before a corrected preview is
