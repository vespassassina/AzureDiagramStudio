# DGM-134: Top-Bar Application Controls

Date: 2026-10-28. Status: COMPLETE / INDEPENDENT SOURCE ACCEPTANCE PASS.
Authority: PO requested "move help, about, settings all on top bar" and
"left bar is only to manipulate the diagram".

## Context And Contract

Move the existing Help, About and Settings controls together into the top bar.
Move the application theme toggle there too: the left rail is for diagram
manipulation, not application information/preferences. Retain diagram tools,
custom-icon import, diagram Commands, clipboard and document/Markdown editing
controls on the rail. Reuse existing controls, handlers and modal guards.
Do not redesign unrelated chrome or change informational content except
location guidance that would otherwise become false.

Preserve keyboard focus return, accessible names, pending drafts/IME,
selection/camera/history, modal exclusion, read-only and Present behavior.
Controls must remain reachable without horizontal page overflow at 390x844,
720x450 and desktop in light/dark. Update Help anchors, About/manual text,
tests and relevant browser harness assumptions about rail location.

## Acceptance And Tests

- Given editing mode, Help/About/Settings/theme are in the top bar and absent
  from the drawing rail; drawing controls remain on the rail.
- Given a pending title/inline/Markdown draft, opening/closing each information
  dialog preserves the draft and document/history, and returns focus correctly.
- Given modal/IME/async/read-only/Present states, existing guards and visibility
  remain unchanged; no duplicate controls or shortcuts.
- Given supported narrow/short/theme cells, actual pointer/keyboard interaction
  reaches these controls and dialogs with no overlap or page-width overflow.
- Source tests, typecheck/build and independent browser acceptance pass.
