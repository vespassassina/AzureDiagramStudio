# DGM-158: Readable Starter Thumbnails And Safe Replacement Prompts

Date: 2026-11-04. Status: APPROVED BEHAVIOR / QUEUED SOURCE FOLLOW-UP.

## Context And PO Decision

PO request: "in new diagram thumbnails are very hard to see.

if i select a new diagram and the current one is saved (or just an unedited
template) do not ask if i want to overwrite"

The PO selected "Skip after Save JSON or for an unchanged template (Recommended)"
after being told browser/app autosave only holds the active recovery copy.
Do not suppress the prompt merely for "Saved on this device" autosave.

Current thumbnails are fixed84x84px inside two-column starter cards. Session
openStarter currently marks a chosen template as not backed up, so an unchanged
template unnecessarily triggers the backupDirty replacement confirmation.

## Contract

1. Make actual New diagram previews substantially larger and clearer while
   preserving complete diagram fit, recognizable artwork and named choices.
   Target at least240x160CSSpx artwork on desktop and a full available-width
   preview on narrow layouts, rather than enlarging empty card padding.
   Keep white artwork background legible in both themes and do not crop content.
   Preserve existing direct choice/Blank/Enter/Escape behavior; no unapproved
   extra Create-confirmation step, hover-only inspection or automatic selection.
2. The chooser remains usable at narrow/short sizes, with reachable controls,
   keyboard focus, scrolling and no document-wide overflow. All actual starters
   remain distinguishable; exercise the most complex templates visually.
3. Before replacing, skip the discard confirmation only when the current
   accepted document has a proven up-to-date JSON backup/opened JSON, or it is
   still equivalent to its original unedited bundled starter/blank baseline.
   Save canceled/failed, stale earlier save or autosave alone is not proof.
4. Template-baseline recognition is separate from backupDirty. Do not claim a
   JSON file exists or mark the template backed up simply to avoid a prompt.
   Editing the template makes it require confirmation until JSON-saved or
   returned exactly to its unchanged baseline via Undo. If provenance cannot
   be proved, retain the guard rather than guessing away user work.
5. Finish/validate existing drafts before deciding. Title, Markdown, colors,
   geometry, routes, state configuration and workbook changes all count.
   Do not treat a nonempty/customized document as pristine just because its
   entity count/title matches a template.
6. Preserve current confirmation on genuine unsaved edits; Cancel leaves all
   content/history/backup intact. Recheck ownership/generation after async
   boundaries/confirmation. Reuse the replacement decision for New/Open/
   template actions and applicable MCP create paths; no safety bypass fork.
7. With workbooks, evaluate the complete root, not merely an unchanged active
   page. Do not discard other edited pages because the visible page is pristine.
   Guide/manual distinguish actual JSON backup, local recovery and templates.

## Given/When/Then And Definition Of Done

Retain executed behavioral RED/GREEN/typecheck/build and source hashes under
`app/test-results/dgm158`. Independent actual chooser/confirmation checks:

- Given a successful unchanged JSON save or opened JSON, selecting a new
  template does not prompt; canceled/failed/stale JSON save still protects edits.
- Given an unchanged template, replacement skips the prompt but the status bar
  still truthfully reports a JSON copy is needed. Editing then replacing asks;
  Undo to exact template baseline removes the unnecessary prompt again.
- Given only successful autosave of an edited document, replacement still asks.
  Declining preserves exact content/history, including Markdown and layout.
- Given workbook edits outside the active page or unfinished/invalid drafts,
  do not infer "unedited" from the active page or lose nonvisible work.
- Given all starters at desktop/narrow/short/light/dark sizes, actual artwork
  is enlarged/unclipped/distinguishable and all choices/close controls remain
  keyboard/pointer accessible. CSS-presence-only tests are insufficient.

No new dependency, persisted template marker/schema migration, new starter
content, unrelated layout/selection redesign, package/version/release/install
or Git delivery. Existing DGM-148 blockers remain separate.
