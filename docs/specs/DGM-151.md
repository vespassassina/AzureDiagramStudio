# DGM-151: Multi-Page Diagram Workbooks

Date: 2026-11-04. Status: APPROVED / QUEUED AFTER DGM-150.
Architecture: [RFD004](../rfd/004-workbooks-and-interoperable-exports.md).

## Context

PO request: "also add multi page diagrams, each is a contained json, shows as
tabs at the bottom like excel.

the workbook can have its own markup description, each diagram has its own md
description and the tabs show also in presentation mode. Export can be done per
page or per workbook.

workbook pages have a title and can be sorted (like in excel by dragging)"

The PO chose one workbook JSON containing self-contained diagram pages, then
"Also include a combined multi-page PDF". The guide must cover new capabilities.
No feature is implemented or installed by this planning record.

The PO subsequently selected "Approve the workbook, PDF and native Visio export
scope (Recommended)", explicitly approving the backward-compatible workbook,
100-page/64MiB bounds and page-aware CLI/MCP scope in RFD004.

## Contract And Acceptance

Follow RFD004's approved workbook envelope, existing diagram/page shape,
backward compatibility, bounds, state/history and export semantics.

1. Open/save/recover all pages, workbook metadata, page metadata and ordering
   exactly. Standalone diagram JSON remains supported and is not silently
   converted/rewritten. Malformed or partially valid workbooks fail atomically.
2. Bottom titled tabs navigate in Edit and Present; drag ordering persists.
   Keyboard alternatives, narrow/short layouts, focus and unsaved drafts work.
   Presentation cannot rename/reorder/add pages. Switching does not lose edits.
3. Workbook Markdown and each page's Markdown edit/preview independently,
   using existing safe rendering, without changing another page/description.
4. Save JSON saves the entire active workbook. Export clearly chooses page or
   workbook. ZIP contains ordered artwork/Markdown plus workbook Markdown and
   manifest; PDF has one fitted titled diagram per page in saved tab order.
   Duplicate titles are safe, outputs are real and no partial file is presented
   as success. Existing per-page export behavior stays compatible.
5. Undo/Redo, revision guards, autosave, Recent originals, CLI and MCP are
   page/workbook aware. Async work cannot mutate the wrong page. Existing
   single-diagram clients retain their contract; new page operations use ids
   and explicit tokens. Native path access stays restricted to approved IO.
6. In-app guide/manual document workbook/page distinctions, tabs, Markdown,
   reorder, save/export scopes, PDF and headless workflows and actual limits.
   No claim that installed0.5.1 has new capabilities.

- [DGM-151C](DGM-151C.md) depends onA/B and accepted DGM-150 render host: page/workbook JSON/

- [DGM-151D](DGM-151D.md) depends onA/B/C and accepted DGM-150: additive page-aware CLI/MCP

## Given/When/Then Verification

- Given distinct pages with overlapping entity ids and independent Markdown,
  when saving/reopening, then exact identity, description, order and geometry
  remain, with no cross-page collisions.
- Given a legacy file, when opened/saved without explicit workbook creation,
  then it remains legacy. Given unsupported version/duplicate page ids or
  one invalid page, then preserve current work and original input bytes.
- Given content/drafts onA, when switching/reordering/undoing fromB, then
  preserve both pages and apply history to the correct page. Late async
  completions cannot move edits/layout ontoB.
- Given Present mode, when navigating tabs, then pages and descriptions update
  without edits or structural controls; temporary ink stays local and unsaved.
- Given ordered pages with same/long titles, when exporting, then ZIP has
  unique safe members and PDF has the exact expected page count/order with
  real unclipped artwork; source and current page remain unchanged.
- Given an older single-diagram CLI/MCP caller, when using existing operations,
  then its supported semantics remain. New book/page operations reject stale
  tokens and target explicit ids; no file-path tool is introduced.

## Out Of Scope And Risks

No cross-page connectors, simultaneous multi-page canvas, cloud/collaboration,
template marketplace, new dependencies, automatic old-file/profile migration,
data deletion, unrelated connector repair or package/release/Git delivery.
VSDX is separately scoped in DGM-152.

Risks: data loss from active-page-only save, misrouted asynchronous edits,
history memory use, unsupported old binary recovery, schema ambiguity, file
limits and PDF runtime availability. Do not change the approved DGM-150
contract silently; this is a later additive feature once approved.
