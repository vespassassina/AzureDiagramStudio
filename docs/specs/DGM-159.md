# DGM-159: Save, Save As, Load And Recent File Workflow

Date: 2026-11-04. Status: APPROVED BEHAVIOR / QUEUED SOURCE FOLLOW-UP.

## Context And Explicit PO Choice

PO request: "the file must have a Save/Load (remove the JSON word). save saves
with current name in the default folder. then Save As allows saving wherever
i want. Load allows selecting the json file to load. then we have the recents
that just makes it faster"

After being asked about files loaded/saved outside the default folder, the PO
selected "Always save in the configured default folder, using the current
filename". Do not substitute standard Save-to-current-external-location.

PO clarification: "when saving or creating a workspace, try to use the name of
the diagram." Also: "since we ahve already a configured workspace, just SAVE
saves there."

## File Workflow Contract

1. File commands read Save, Save As and Load, not Save JSON/Open JSON.
   JSON remains the actual editable file format/filter; do not rename public
   MCP JSON format ids or hide file extensions. Recent diagrams is a shortcut
   to Load originals, not a separate snapshot/document engine.
2. Save writes the complete committed active document/workbook into the
   configured default folder, using its current filename, without a location
   picker. The configured folder is the Settings workspace root, not a new
   silently chosen folder. New untitled documents derive a safe initial name
   from the document/workbook title; established file names stay independent
   of page/title changes. Preserve legitimate selected filename Unicode/spaces.
3. Save As opens the native destination dialog, allows an arbitrary user-chosen
   location/name and updates the current filename on successful write.
   A subsequent Save still targets the configured default folder with that
   filename, even if Load/Save As used another folder. Never quietly overwrite
   that external original as a side effect of Save.
4. Load selects a JSON file and uses existing validation, current-data reads,
   size/ownership/generation guards and truthful replacement protection.
   Recent performs that same guarded Load through an opaque registered id.
   Successful Save/Save As/Load promotes/adds the exact original path.
5. In a workbook, Save/Save As writes all pages, metadata/order/descriptions;
   the active page does not determine the filename or clear backup on its own.
   Page-only JSON remains an explicit Export operation, not a competing Save.

## Diagram-Based Naming And Existing Workspace

When suggesting an initial filename or explicitly creating a workspace, prefer
the diagram title (workbook title for a workbook), made filesystem-safe. Do
not expose an opaque id as the default human-facing name. Preserve explicitly
chosen names and apply the existing collision/safety rules.

An already configured workspace is authoritative: Save writes there directly.
It must not ask the user to configure/select a workspace again, create a new
per-diagram workspace, or silently change the configured location. Suggesting
a name during explicit workspace creation does not authorize renaming/moving
an existing folder or changing its contents.

## File Safety And State

Native Save accepts only a safe basename and a validated supported document
payload; derive the destination under the resolved configured root in main.
Do not expose a path-taking renderer/MCP writer. Preserve native trusted-frame,
async active-sender, regular-file/redirection and byte bounds checks.
Do not change GUI HTTP auth or add MCP filesystem tools.

Create only app-owned default directories under a usable OS Documents root.
An unavailable explicitly configured folder reports an error, not fallback
or recreation. Existing per-document export folders are not moved/deleted;
this is an explicit new Save default, not a data migration.

Use atomic file writes. Known current-document/default-file updates need no
extra location confirmation; a filename collision with unrelated/unverifiable
existing content needs an explicit overwrite decision, never silent clobbering.
Native Save As retains its overwrite confirmation. Decline/cancel/failure leaves
old files/state intact; file saved plus Recent failure is truthful partial
success, not a false failed write or a false fully recorded save.

Track current filename separately from document title/page title without adding
it to diagram JSON. Backup state reflects the exact successfully written root
snapshot; late completion cannot clear a newer document's dirty state.
Browser-only Save/Save As may only use supported download/picker capabilities
and must clearly state they cannot guarantee a Settings-controlled filesystem
destination. Do not claim desktop semantics for a download.

Replacement decisions follow DGM-158: actual up-to-date JSON file backup or
unchanged template can skip the prompt; autosave-only cannot. No new bypass.
Keep existing shortcuts but distinguish Save/Save As consistently in help.

## Given/When/Then Verification

Retain executed behavioral RED/GREEN/typecheck/build and hashes under
`app/test-results/dgm159`; independent isolated native IO and actual UI checks.

- Given a named document, Save writes configuredRoot/currentFilename without
  a picker; repeated Save updates that document atomically.
- Given an existing configured workspace, Save neither opens workspace setup
  nor creates/selects a new diagram-specific workspace.
- Given a new unnamed document or explicit new-workspace action, suggest a
  safe name based on the diagram/workbook title; preserve an explicit chosen
  name and leave existing workspaces unchanged.
- Given Load/Save As outside the root, Save writes a root copy under the same
  filename, leaves the external file exact and records/promotes the right path.
- Given a title/page switch, established filename stays unchanged. New unnamed
  work derives a safe default without traversal/reserved names; valid selected
  Unicode/spaces survive. No renderer-supplied path can escape configuredRoot.
- Given unrelated existing same-name file, unavailable root, symlink/redirection,
  permissions failure or stale sender, preserve bytes and report explicitly.
- Given Save As cancel or file/Recent partial failure, current filename/backup/
  Recent state reflects the exact actual outcome; no fake file backup.
- Given a workbook with edits on nonactive pages, Save persists all pages.
  Load/Recent and DGM-158 confirmations share one safety path.
- Given browser-only runtime, labels and explicit capability limitations are
  honest; desktop behavior is not inferred from a browser download.

Update manual/in-app guide/Settings descriptions and current command labels.
No new dependency, arbitrary file API, automatic migration, package/version,
release/install, global configuration or Git delivery.
