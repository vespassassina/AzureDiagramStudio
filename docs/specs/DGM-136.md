# DGM-136: Export Diagram With Companion Markdown

Date: 2026-10-28. Status: COMPLETE / INDEPENDENT SOURCE ACCEPTANCE PASS.
Authority: PO requested "also add to export the option to export the markdown
with the diagram" and selected "Download a ZIP containing the diagram and a
companion .md file; offer the same pair through MCP (Recommended)".

## Context And Contract

Add an optional, default-off "Include Markdown" checkbox to the existing export
dialog. With it off, current SVG/PNG downloads remain unchanged. With it on,
download one ZIP containing exactly the normal exported diagram and a companion
UTF-8 `.md` containing its architecture description. Both members share the
normal safe export filename stem. The outer filename ends in `.zip`, MIME
`application/zip`. Keep all image export options effective.

The Markdown is the committed document's description, not a pending draft,
rendered HTML, generated prose, or app UI. Preserve its bytes/newlines; an
absent/empty description produces an empty `.md` (no invented content).
Both members derive from the same captured committed document. No execution,
external loading, filesystem path access or conversion of inert Markdown.
No document/history/selection/camera changes and no silent export failures.

Reuse one shared archive helper from UI and DGM-135's MCP export. Use existing
available code/dependencies or a small standards-compliant uncompressed ZIP
writer with UTF-8 filenames, CRC32, explicit size limits and deterministic
metadata; no dependency addition. Reject unsafe/path-like names and excessive
member/archive sizes. No compression feature is required.

## Acceptance And Tests

- Given Include Markdown off, existing SVG/PNG download name/MIME/bytes persist.
- Given Include Markdown on, an independently decoded ZIP contains exactly the
  selected SVG/PNG plus matching `.md`, correct CRC/lengths and UTF-8 content.
- Given empty/Unicode/hostile Markdown or filename-like title, Markdown remains
  inert and exact, archive names are safe, and no extra entries/paths appear.
- Given async capture and subsequent document edits, image and description stay
  paired to the captured document; pending drafts are never silently committed.
- Given invalid/too-large/failed image/archive output, export reports an error
  without a partial download or state/history change.
- Checkbox is accessible and usable in supported responsive/theme cells;
  source tests, typecheck/build and actual browser ZIP download pass.

## Ownership And Scope

UX implementer owns scoped export contracts/session/dialog/archive helper/tests
and README/manual guidance, plus retained RED/GREEN evidence.
Independent verifier checks browser download and independently decodes archive,
never repairs product code. Shared helper exports allow DGM-135 to offer the
same pair as a base64 MCP ZIP resource with optional `includeMarkdown: true`.
No new dependency, security, app version, package, tag, publication, user
profile or external state changes. Preserve DGM-133 and the running app.

## Additional Export Format - 2026-10-28

The PO additionally requested "also export adds an option to export markdown
doc with png embedded". Add `markdown` alongside SVG/PNG as a UI export format
and in DGM-135's export tool. This produces a single UTF-8 `text/markdown` `.md`
file containing the committed architecture description and a diagram image in
standard Markdown image syntax with an inline `data:image/png;base64,...` URI.
Use fixed safe alt text and a clearly separated image block; preserve the
description verbatim. An empty description still exports the embedded diagram.
Render PNG using the selected existing image options (scale/background/aspect/
grid/transparency). Capture image and description from the same document.

The companion-Markdown ZIP option remains available only for image/native JSON
formats, not for markdown itself; UI hides/disables it for markdown and MCP
rejects includeMarkdown true with format markdown instead of double-wrapping.
Never silently reuse an enabled ZIP flag when switching to markdown.
Share formatting/encoding between UI/MCP, retain bounds and explicit failures.
Tests independently decode the inline PNG and compare the description and
same-state output. Document that some Markdown viewers disallow data images;
ZIP is the portable alternative. No new dependency or HTML conversion.
