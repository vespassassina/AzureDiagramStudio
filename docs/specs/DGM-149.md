## Behavior And Acceptance Criteria

1. File -> Recent diagrams opens one accessible modal, not a second toolbar
   home or an automatic startup window. Show up to20 entries, newest first,
   with file name/path and last successful open/save time. Distinguish files
   with identical names. Show honest loading, empty and failure states.
2. Remember only successful user Open JSON and successful JSON file saves.
   Deduplicate the same original path and promote on successful reuse.
   Remember per desktop app profile across restart. Do not treat browser
   autosave, an unaccepted open, skill import, image/Markdown/ZIP export,
   template selection or MCP in-memory output as a recently saved JSON file.
3. Selection reads the current original file, not a cached diagram snapshot.
   Reuse full document parsing,5MiB JSON bounds, unsaved-work confirmation,
   request/generation ownership guards and replacement semantics. Missing,
   moved, unreadable, oversized and invalid files report explicit errors;
   they leave the current document/history/backup state and recent order intact.
   No silent search, relocation, snapshots or fallback file is allowed.
4. Native registration originates only in a native user file dialog or a
   completed native JSON save. Reopening accepts an opaque registered ID, never
   a renderer-supplied path. Require trusted active main-frame IPC sender,
   exact argument shapes and rechecks after async boundaries. Bound pending
   tokens, persisted input and file reads; do not expose this facility to MCP.
   A selected file becomes recent only after successful renderer acceptance.
5. History writes are bounded, validated and atomic. Corrupt/unwritable
   history reports explicitly without overwriting existing bytes or harming
   diagram files. Distinguish "file saved, recent list failed" from a failed
   file save, preserving truthful backup state. No silent persistence failure.
6. Modal keyboard access, focus trap/return, Escape/Close, theme contrast,
   long paths and narrow/short layouts work. Underlying editor shortcuts,
   mutations, Present and MCP writes are blocked while the dialog owns input.
   Closing without choosing does not alter current work. Preserve normal
   draft-finalization and ownership/loading guards; do not invent a separate
   replacement path. Browser-only builds retain normal Open/download behavior
   and clearly explain desktop-only original-file history.
