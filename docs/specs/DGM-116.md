# DGM-116: App Icon Refinement

Date: 2026-10-12. Status: APPROVED / FROZEN BY LATEST PO REQUEST.
Context: PO asked "status can we have a nicer icon?" during approved Sprint 4.
This is a bounded original-brand asset refinement, not a product rename or release.
Baseline: [DGM-070 branding contract](DGM-070.md#branding-owner).

## Frozen Scope

Retain Azure Diagram Studio's exact name and the existing original architecture
mark direction: teal badge, white diagram nodes/connections and a distinct blue
accent. Refine silhouette, spacing and connection geometry; remove tiny inset
label bars that compete with the graph at favicon sizes. Use three simple filled
nodes joined by a visible continuous orthogonal connection, with the blue node
distinct and all artwork comfortably inside the badge. No official Microsoft,
Azure, Fabric or vendor glyph becomes our branding. No lettermark, new font,
dependency, service artwork or editor layout change.

The one canonical source remains `app/public/branding/logo.svg`, accessible with
the existing product title and an original-mark description. Existing generation
produces SVG favicon, PNG sizes 16/24/32/48/64/128/256/512 and multi-resolution
Windows ICO files. Regenerate through the existing script; do not hand-edit binary
assets or create inconsistent independent favicon art. Existing paths stay fixed.

## Ownership and Cases

Implementer owns only the canonical vector, generated branding/favicon artifacts
and existing `app/scripts/generate-brand.test.mjs`. Generator production code,
editor code/styles, icon registries, examples, desktop/config/security and release
files are read-only. Orchestrator owns this spec and decision/review documentation.

1. Given the original source, a red regression checks simple three-node topology,
   absence of tiny internal bars and self-contained accessible artwork. After the
   refinement, the same check passes; existing title/header assertions stay intact.
2. Render 16/32/256px with existing Edge tooling. Artwork is nonblank, unclipped,
   retains transparent exterior, and node/connector contrast is inspectable.
   Pixel evidence supplements visual inspection, not an invented aesthetic score.
3. Two independent generations exactly match cached PNG/ICO/SVG bytes. Existing
   ICO sizes and offline generation policy remain unchanged.
4. Production desktop/mobile headers display the new mark without changing name,
   document behavior, brand slot dimensions or word wrapping. Capture screenshots.

Use mandatory red/green/refactor in the existing generator test, retain failure
logs, validate immediately after each substantive edit, then build the source app
and independently run the scoped brand tests. Do not weaken existing tests.

## Done and Exclusions

Done: coherent generated source assets, current passing scoped tests/build, actual
small-size and header screenshots inspected, and limitations stated. Existing
published desktop executables retain their old embedded icon until a separately
authorized rebuild/release. No packaging, publication, CI, signing, commits,
new dependencies or platform promises. Approved Sprint 4 tasks remain pending;
this small PO-requested asset refinement does not waive its final review stop.
