# DGM-152: Native Visio Export

Date: 2026-11-04. Status: APPROVED / QUEUED AFTER WORKBOOK EXPORT CONTRACTS.
Context: PO asked "can we add visio export ?".
Architecture: [RFD004](../rfd/004-workbooks-and-interoperable-exports.md).

The PO selected "Approve the workbook, PDF and native Visio export scope
(Recommended)" after reviewing native editable VSDX, ordered workbook pages
and embedded-image icons. This approves source implementation, not target-
application acceptance, packaging or installation.

## Approved Contract

Add native .vsdx export for a single diagram/page or all workbook pages in tab
order. Use actual Visio OPC/XML drawing parts, editable component/shape/text
objects and connected connectors, not a renamed SVG or a flattened screenshot.
Preserve titles, layout, connection endpoints, arrow/dash styles and supported
group intent. Icons may be embedded images; disclose this rather than promising
editable vendor master stencils or exact native round-trip reconstruction.
Keep original JSON as the authoritative editable Diagram Studio document.

Use existing ZIP support, XML escaping and shared scene geometry; no dependency
or Visio automation installation is approved. Macro-free .vsdx only, no external
resource relationships, active content or remote image dependencies.

UI export and page/workbook scope, native save MIME/extension validation, CLI
`--format vsdx` and in-memory MCP resource output must agree. No arbitrary-path
MCP operation or security-policy weakening. Guide/manual explain workflow,
supported editability, limitations and source-versus-installed status.

## Acceptance And Tests

1. Retain pre-implementation RED/GREEN. Verify deterministic valid ZIP/OPC/XML,
   every relationship/content type/page mapping, escaped Unicode/special text,
   unique safe part names and no macros/external references.
2. One page exports to one Visio page; a workbook exports all pages in saved
   order with titles and independent shape/connector ids. Same-name titles or
   page-local duplicate entity ids never collide.
3. Real Visio open has no repair dialog; page count/order/titles and artwork
   are correct. Move an exported shape and verify its connector remains glued;
   edit labels/shapes. A ZIP/XML inspection alone is not editability evidence.
4. Icons/images remain embedded offline; geometry, backgrounds and supported
   boundary/connection styling match the source within declared tolerances.
   Test straight/bent paths, negative origins, nested groups and long labels.
5. UI, headless CLI and MCP generate the real target format with honest errors,
   original source unchanged and no misleading partial-success file.

Independent verifier records exact source/output hashes, structural tests and
target-application evidence. If Visio is unavailable, mark that interoperability
cell BLOCKED and continue independent ready work; do not install software,
fabricate a pass or equate another application's renderer with native Visio.

## Dependencies And Boundaries

Implementation references verified on2026-11-04:
[VSDX packaging introduction](https://learn.microsoft.com/en-us/office/client-developer/visio/introduction-to-the-visio-file-formatvsdx),
[Connect element](https://learn.microsoft.com/en-us/office/client-developer/visio/connect-element-connects_type-complextypevisio-xml),
[Connection row XML](https://learn.microsoft.com/en-us/office/client-developer/visio/row-element-connection-sectionvisio-xml)
and [connection point coordinates](https://learn.microsoft.com/en-us/office/client-developer/visio/connection-points-row-connection-points-section).
Use the native VSDX `http://schemas.microsoft.com/office/visio/2012/main`
schema, not the differently scoped2011/core Web Drawing appendix. Glued
connections need proper source/target shape/cell references, not only visually
coincident coordinates. Custom connection point coordinates are shape-local;
their formulas must follow shape dimensions so normalized anchors survive
resize. These references guide implementation, not target-application evidence.

Depends on accepted DGM-150 and DGM-151 page/export contracts. A native single-
page writer can be verified before multi-page integration but may not claim
whole-workbook acceptance prematurely. No VSD/VSS stencil import, bidirectional
Visio import, vendor stencil library, PDF change, package/release/install,
global automation config, Git delivery or unapproved dependency.
