## Editing UI

Add an accessible compact Edit/Preview segmented control directly above the
description box in document Properties. Reuse one description editor/preview
component for this compact box and a full-height Markdown sidebar view. Preview
reflects the current description, including its valid pending draft. Switching
Edit/Preview, Properties/Markdown or opening Markdown must not silently discard
or commit a pending description; retain existing explicit blur/finish/cancel,
single accepted Undo, IME, Help/chooser, document-switch and read-only rules.

Add a FileText/book-style icon button immediately next to the existing Properties
button in the drawing rail and canvas panel controls, labelled "Open Markdown".
It opens the same right bar in Markdown view without clearing the selected
object or moving the camera. Properties returns to the existing entity/edge/
document properties context. Header controls allow switching views; do not
duplicate editable textareas or introduce a second document-description state.
Edit and Preview both work in Markdown view outside Present. Read-only can
read/edit-mode source but cannot modify it, and can always choose Preview.
Keyboard focus and native text-selection shortcuts must not trigger background
canvas delete/cut/paste when the Markdown preview owns focus.

## Shared Right Bar And Presentation

Make the shared right bar pointer-resizable from its left edge and keyboard-
resizable through an accessible separator (Arrow keys, Home/End). Clamp to
usable widths and viewport bounds; support scroll for long prose/code/tables
without horizontal page overflow. A collapse/close control hides it; the
Properties/Markdown buttons remain discoverable to reopen it. Remember width
for the current editor session, not in diagram JSON. Escape during active
sidebar resize cancels only that resize; normal Escape behavior otherwise stays.

In Present expose a Markdown toggle beside the existing presentation controls.
When a description is present, show a readable Markdown preview on entry; empty
descriptions may keep the bar collapsed but must remain openable. Present never
offers description mutation or editing properties. The bar is resizable,
collapsible and reopenable, and its preview stays selectable/scrollable.
Capture the pre-Present panel view/mode/width/open intent and restore it on Exit
with existing exact camera/selection/focus behavior. No document/history change
from preview, resize, collapse or presentation reading.

Support the sidebar in fullscreen too: place it inside the fullscreen ownership
boundary or adjust the internal fullscreen container without changing browser/
Electron security behavior. Preserve the existing Exit, pointer, drawing markup,
pan/zoom, ink history and active-stroke/idle Escape rules. Dock on roomy screens;
a bounded overlay is acceptable on narrow screens, with Exit and collapse/reopen
reachable above it. Collapse must restore access to drawing/navigation without
losing diagram or temporary ink. Keep real content/controls from overlapping
incoherently or being trapped offscreen. Follow light/dark/reduced-motion tokens.
