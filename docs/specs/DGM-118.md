## Acceptance Cases

1. Given one writable selected component, its contextual toolbar has a named,
   keyboard-focusable Trash2 button with tooltip. No selected component means
   no quick-delete button. Other entity kinds and multi/mixed selection do not
   expose it. Existing four connected-component actions remain usable.
2. Given a component with incident connections and unrelated content, activating
   the new button emits the existing removal command for that component only.
   The domain removes its incident connections and one Undo restores the exact
   prior document. Do not introduce a second mutation for the same activation.
3. Given read-only/loading, Present, Help/modal, composition or stale context,
   the button/handler cannot bypass the established mutation guards. Do not
   silently discard a draft or weaken existing acceptance to obtain a pass.
4. Given desktop/mobile and light/dark UI, the icon is discoverable, hit-tested,
   reachable and not clipped or overlapping diagram labels/connection handles.
   Physical Enter/Space activates it; its event does not start drag/connection
   or create a second deletion. Existing quick-add behavior remains correct.
