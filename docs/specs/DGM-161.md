# DGM-161: Token-Free Loopback MCP And Stable Configurable Port

Date: 2026-11-04. Status: IMPLEMENTED / INDEPENDENT PACKAGED-RUNTIME CELLS PASS;
WHOLE-BUILD AND DGM-153 ACCEPTANCE REMAIN SEPARATE.

The initial independent verifier was canceled before any completed turn when
the PO requested immediate compile/run. The later independent actual-runtime
checks passed on the frozen unverified0.5.2 ARM64 candidate using owned

report](../verification/DGM-161.md). That narrow result does not accept

## Context And PO Authority

PO request: "remove the access token requirement. and allow changing the port
(keep it stable)".

The PO explicitly confirmed "Yes--localhost only, no token, persistent
configurable port (Recommended)" and "Apply after restart; never silently change
ports (Recommended)". This authorizes this bounded authentication and local
configuration change, not network exposure or unrelated security changes.
Include it in the pending local 0.5.2 delivery before packaging.

The current desktop server binds127.0.0.1, generates a per-launch bearer token
and silently falls back to an ephemeral port on collision. Settings copies the
address/token but cannot configure the port. Replace those behaviors without
changing diagram commands, schemas, state tokens or session safety.

## Interfaces And Behavior

- Keep the listener bound exclusively to127.0.0.1. Do not bind wildcard/LAN
  addresses, add a proxy, enable remote access or change firewall settings.
- Valid local MCP requests no longer require Authorization. Remove bearer
  generation, comparison and token-copy UI/preload/IPC. Existing clients that
  still send an Authorization header remain usable; do not log its contents.
- Preserve exact Host validation, rejection of browser Origin/cross-site
  requests, HTTP/content-type/protocol validation, body/concurrency/time limits,
  trusted renderer IPC and shutdown/fault protections. Do not add permissive
  CORS. All diagram revision/state-token, draft/modal/Present/ownership guards
  remain: the access token is NOT the diagram state token.
- Add one MCP port control under the existing Settings / Local MCP server
  section. Default37431 remains when no preference exists. Valid user ports
  are integers1 through65535;0, nonfinite/fractional/coerced malformed values
  are invalid. No address/host setting.
- Persist the chosen port atomically within the existing app profile. Other
  profiles, workspace files and diagrams are unchanged. Reuse existing bounded
  settings/atomic-write patterns; no dependency or automatic document migration.
- Save port applies on the next app launch, not by restarting/rebinding the
  current listener. Show the actual current address separately from the saved
  next-launch port and make pending-restart feedback explicit. Preserve the
  user's in-progress port input during status refresh.
- Never silently select another port when the configured one is occupied or
  unavailable. Keep the editor usable, report the listener failure and let the
  user save another port even while MCP is unavailable. Restart is user-owned;
  do not close the app or modify another process.
- Missing preferences use the documented default. Invalid/unreadable existing
  preferences produce explicit settings/listener feedback, not a successful
  default fallback. An explicit valid Save may repair the port preference;
  failed persistence leaves the prior durable value intact and reports failure.
- Renderer bridge adds `readPort(): Promise<number>` and
  `savePort(port: number): Promise<number>`. Main owns validation, bounded disk
  access and persistence; expose no arbitrary path/file operations. Remove
  `copyToken`; retain `status`, `copyAddress` and existing diagram operations.
  Internal settings/server composition remains the implementer's choice.
- Existing transport tests may explicitly request an ephemeral constructor
  port as an isolated fixture seam; production preferences never accept0 and
  startup never uses ephemeral fallback.

## Tests And Acceptance

Follow executed RED -> GREEN -> refactor with first-run logs under
`app/test-results/dgm161`. Preparation outside normal discovery is not RED.
Implementer and independent verifier stay separate; shared source/build/
terminal ownership remains serial.

1. Given a valid non-browser loopback client without Authorization, initialize,
   read and normal guarded mutation/output work. An old Authorization header
   does not prevent these requests. No token-copy API/control remains.
2. Given a foreign Host, any browser Origin or cross-site request, reject it
   before diagram access. Existing method/MIME/protocol/size/concurrency/time
   and trusted-sender tests stay effective. Preserve the mutation state token.
3. Given absent settings, launch on37431. Given a saved valid port, fresh
   settings/server instances use exactly that port across restarts. Given a
   collision, no other listener appears and the editor reports failure.
4. Given malformed,0, out-of-range, fractional, nonfinite or otherwise invalid
   input/configuration, reject it with feedback and no successful fallback.
   Given atomic-write failure or concurrent saves, preserve existing durable
   settings and report the unsuccessful operation.
5. Given Settings opened while running or unavailable, keyboard/pointer users
   can edit and save a valid port. Invalid input cannot save. Current address
   stays unchanged until restart; pending-restart and failed-save feedback are
   honest. Status polling cannot overwrite an input draft. Focus trap/Escape,
   narrow layouts and browser-only guidance remain usable.
6. Exercise a real production renderer and actual native IPC/preferences in
   isolated profiles, including two starts on the same saved port and a port
   collision. No old profile, live app or real Documents workspace is modified.
   Exact-portable DGM-160 qualification must then cover the final integrated
   token-free server, saved port and normal guarded MCP operations.

## Out Of Scope And Risks

No live port rebinding, remote/LAN/IPv6 support, token-optional mode, new auth
mechanism, headless feature work, schema/tool changes, shell/filesystem tools,
installation, GitHub publication, dependency upgrades or closing other apps.
All local non-browser processes can now read/edit through MCP while the app is
open; explain this plainly rather than claiming localhost authenticates clients.
Port conflicts between separately running profiles are now explicit failures,
not random-address success. Preserve current work while letting the user
configure a distinct stable port.
