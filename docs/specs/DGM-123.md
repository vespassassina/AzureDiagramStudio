## Topology And Guide Constraints

Use existing validated catalog icons/aliases and only current available choices;
when no exact service glyph exists, use an honest generic icon with the correct
service name. No new icon/dependency downloads. All diagrams and represented
components are synthetic, never live/deployed. Boundaries show intended owners
or trust domains, not verified security or connectivity. Keep 6-12 meaningful
components, roughly three boundaries and short directed-flow labels. Use the
existing native schema and app ELK/layout/scene utilities or the loaded
architecture skill for deterministic geometry; inspect actual rendered output.

- AKS: clients -> Application Gateway -> internal load balancer -> Envoy ->
  stateless workloads. Show registry/secrets access via private endpoints,
  separate firewall egress and monitoring. Do not claim TLS to every workload
  hop, or treat infrastructure baseline as a microservice domain design.
- Container Apps: ingestion -> Service Bus -> workflow -> scheduler/delivery,
  service-owned Cosmos DB/Managed Redis state, registry/secrets/monitoring.
  Omit the package-service branch because the source conflicts between Cosmos
  DB and Azure DocumentDB. This is a brownfield example, not universal baseline;
  do not invent a WAF on its initial ingress.
- Web/queue/worker: App Service front end, Storage queue, Functions worker,
  SQL result/status store. Cache/Cosmos/remote services are optional dashed
  extensions; web reads can go directly to data. Queue/database writes are not
  automatically atomic and must not be described as exactly-once delivery.
- Hub/spoke: platform hub firewall/Bastion/monitoring/Network Watcher, two
  separately owned spoke workloads and optional VPN/on-premises path. No default
  spoke-to-spoke edge; peering is nontransitive and requires explicit routing.
- Stamps: tenant clients -> Front Door -> API Management -> tenant/stamp map,
  two independent App Service/SQL stamp units. No implied cross-stamp data
  replication, automatic regional failover or guaranteed tenant isolation.
- Claim check: sender uploads Blob -> Event Grid -> Service Bus -> Functions;
  consumer separately fetches payload from Blob. Logical payload/reference nodes
  are not extra Azure services. References do not confer storage authorization;
  describe idempotency, retention and duplicate/delayed delivery considerations.
- Warehouse: periodic SQL Server/Oracle/Azure SQL exports -> Data Lake Storage;
  Data Factory -> Synapse -> Analysis Services -> Power BI. This source retains
  a 2022 authored date despite a 2026 update; do not advertise it as newly
  authored, silently relabel Analysis Services as Fabric, or add Fabric Datamart.
