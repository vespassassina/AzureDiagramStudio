## Context and Observed Contracts

Read [lessons](../lessons.md), [current plan](DGM-100.md) and the nearby
[DGM-108 spec](DGM-108.md) before authorized work. Observations below describe the
current dirty source tree, not a qualified packaged release or new test result.

- [SaveState and EditorProps](../../app/src/contracts.ts) expose `loading`,
  `saving`, `saved`, `error`, `read-only`, `backupDirty`, `message`, `readOnly`,
  `onNew`, `onOpen`, `onImport` and `onSaveJson`. Keep these names and signatures.
- [Session](../../app/src/app/session.ts) owns one active document and history.
  Autosave has a 500ms debounce and ordered immutable writes; only the latest
  generation can publish `saved`. A local write does not clear `backupDirty`.
  Ownership loss disables mutation; load/lock errors fail closed. A write error
  reports actionable guidance while allowing editing and JSON download.
- `backupDirty` compares canonical JSON with an in-memory backup marker, not a
  file on disk. Load resets the marker to null even for a locally saved document.
  New uses `createDocument(newId())` and `replace(document, true)`; native Open
  uses `replace(document, true)`; skill Import uses `replace(document, false)`.
  Thus false does not prove that an OS file was created, especially for Blank.
- `saveJson()` captures canonical document/generation, formats editable JSON and
  awaits `download`. Resolution clears the marker only if that exact document
  is still current. Rejection publishes `JSON download failed: ...`. Image
  export/copy is separate and does not establish an editable JSON backup.
- [Browser dependencies](../../app/src/app/browser.ts) supply `confirmReplace()`:
  "Replace this diagram? Changes since your last JSON download are not backed
  up. Browser autosave is not a file backup." New confirms when backup-dirty.
  Open/Import validate first, Import completes layout, then confirm immediately
  before replacement; rejection keeps the prior document/history. Replacement
  clears history/preview, invalidates requests and schedules local autosave.
- Open/Import retain request/generation and `canMutate()` guards. Newer edits,
  previews, file choices, ownership loss and Present prevent stale replacement.
  Entering Present invalidates pending file/layout work; exit cannot resurrect it
  or regain an independently lost storage lock. Existing autosave may finish.
- [App](../../app/src/App.tsx) only opens hidden pickers through `canMutate()`.
  Their ARIA names are `Open document file` and `Import skill file`; cancel or an
  empty change supplies no file and does not invoke session replacement.
- [EditorSurface](../../app/src/editor/EditorSurface.tsx) renders `SAVE_LABELS`,
  `.save-label`, `.backup-state`, an inspector save footer and `role="status"`.
  Existing action identifiers are `New diagram`, `Open JSON`, `Import skill JSON`
  and `Save JSON`. `fileAction` finishes a valid draft before invoking callbacks;
  Present blocks it, and mutations additionally require writable ownership.
  Canonical replacement cancellation does not undo an already finalized draft.
  Shell `saveJson()` can still export in read-only/Present; the current Present
  UI hides ordinary file controls. Do not claim a new Present file control.

## Save Cancellation Boundary

[Browser download](../../app/src/export.ts) returns void after clicking a blob
anchor. [Desktop session policy](../../app/electron/security.mjs) allows selected
blob/MIME downloads and sets native save-dialog options; it does not report
DownloadItem completion/cancellation to the renderer. [Desktop main](../../app/electron/main.mjs)
loads the same bundled app. No observable completion acknowledgement exists here.

Consequently the renderer can advance its backup marker before a native save
dialog is canceled or a download fails later. This is a source-level limitation,
not a reproduced native-platform result. Neither successful OS write detection
nor cancellation-aware reminder repair is in this task. Changing the adapter,
IPC/security surface or download return contract requires separate PO approval,
scope and red/green tests. Until then, labels must not claim "file saved",
"backup safely stored" or cancellation detection.

## Proposed Scope and Copy

Keep the existing callbacks, ARIA action names, local persistence semantics and
single-document model. Refine short state copy using the existing status surfaces:

| Current state | Proposed copy | Meaning, not a guarantee |
| --- | --- | --- |
| `loading` | Loading local work | Ownership/load is pending |
| `saving` | Saving locally | Latest local persistence write is pending |
| `saved` | Saved on this device | Current-generation local write/load succeeded in this browser/profile, not cloud sync or a JSON file |
| `error` | Local save failed | Preserve existing actionable error and fail-closed rules |
| `read-only` | Read-only | Another ownership/error guard still governs mutations |
| `backupDirty: true` | Editable JSON copy needed | Canonical content differs from the session's JSON marker |
| `backupDirty: false` | No newer JSON changes | Marker matches canonical content; no OS file-write assertion |

The table's copy is frozen by the approval above. Do not rename `Save JSON`
or conflate editable JSON with SVG/PNG/image clipboard. Preserve independent
local-save and JSON-copy states, including local success with JSON copy needed
and local failure with an available JSON action. Wrap compact text without
overlap; do not add tutorials, a new save workflow or a misleading success toast.
