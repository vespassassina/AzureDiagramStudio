# DGM-157: Page-Scoped Functional State Styles

Date: 2026-11-04. Status: APPROVED / SOURCE IMPLEMENTATION QUEUED.

## Context

PO request: "at page level, allow customizing the styles of connectors, boxes
and colors to map specific functional states.

today this is fixed (see: planned, live, synthetic) but it should be
configurable. MCP can configure this. the current version is a default.

the diagram page can open a popover to configure (add, remove, edit existing)
the available styles and what these mean.

this info is then used in the building of the diagram and the legend. this
is an advanced feature. but can and will be used by MCP and agents."

Existing status styles are hard-coded in scene.ts; entity status and its UI
options are fixed. Legend generation already includes used statuses. Replace
that fixed source with one validated page-local registry, not a separate UI,
MCP and export interpretation.

## Approved Data/Behavior Contract

The PO approved [RFD005](../rfd/005-exact-anchors-and-grid-style.md), including
its concrete64-entry registry, id/name/meaning bounds, validated box/connector
paint fields and canonical status reference. Use that exact public shape.

Each state style has a stable id, readable name, plain-text meaning, validated
box paint settings and connector paint settings. Restrict values to supported
colors/line styles/widths, not arbitrary CSS, SVG, JavaScript, URLs or templates.
Supported fields/bounds are frozen in RFD005 for assignment.

Undefined registry resolves to the current Live, Planned, Not connected and
Synthetic defaults with unchanged existing appearance. An explicit empty
registry means no available styles, not "reset to defaults". Existing authored
states are not silently renamed or remapped.

Entity/connection state references resolve within that page only. A configured
state controls its defined paint fields; unspecified fields preserve base
appearance. Do not mix independent conflicting meanings for status/styleId.
Use one canonical state reference per item, with version1 status compatibility.
Adding a box/connector can assign any defined state, including through MCP.
No automatic inference of real deployment state from colors or labels.

Editing a state updates all its users and legend consistently without changing
geometry, ids, attachment points or another page. Unreferenced removal is
straightforward; removing a used style requires an explicit replacement or
explicit Unset mapping, applied atomically. No dangling references or silent
fallback. Renaming retains stable id and existing item assignments.

## Advanced Page Popover

One canonical Page styles control in page Properties opens an accessible
advanced configuration popover. Avoid a new always-visible application toolbar
or opening it automatically on selection. Show current defaults/custom states
with visual samples, name/meaning and add/edit/remove controls.

Use explicit Apply/Cancel with validation and one Undo transaction; drafts are
not committed/published to MCP while typing. Escape cancels, focus returns to
the opener; outside pointer movement must not silently dismiss edits. Respect
modal/typing/Present/ownership guards and existing sidebar/draft intent.
No editing in Present/read-only mode.

## Legend And Shared Output

Use configured names, meanings and visual keys in both diagram authoring and
legend generation. Include used state ids once each, not every unused preset;
preserve authored manual legend entries. Equal colors with different meanings
are not the same state and must not be merged.

Default files retain current legend behavior/appearance. Custom states propagate
through editor, Present, page/workbook save/reload, SVG/PNG/PDF/Markdown/ZIP/Visio
and headless outputs wherever those formats support the corresponding feature.
Do not silently flatten custom states back into the fixed four labels.

## MCP/CLI Contract

Agents can discover the resolved page registry/defaults, add/edit/remove states,
assign them during item creation/update and read the generated meanings/legend.
Use stable ids, explicit page context and current state tokens. Configuration
and reference remapping are validated/atomic, with actionable errors for invalid
ids/colors/widths, duplicate ids, missing references and stale state.
Reuse existing validated command/service paths, no arbitrary code or filesystem
tools. Exact additive schemas freeze after the shared format approval.

## Test Cases And Definition Of Done

Retain executed behavioral RED/GREEN/typecheck/build and hashes under
`app/test-results/dgm157`; independent real UI, MCP and output verification.

- Given no custom registry, resolve the exact current four presets and preserve
  existing entity visuals/legend/JSON, not an automatic migration.
- Given two pages with matching style ids but different meanings/colors, edits
  remain page-local across save/reload, presentation and workbook export.
- Given renamed/edited style, all referenced boxes/connectors and legend update;
  unrelated state/geometry/attachments remain exact and Undo restores all.
- Given removal of a used style, require explicit remapping/Unset, apply as one
  edit and never save a broken reference. Explicit empty differs from defaults.
- Given malformed/oversized configuration, getters/code-like input or stale
  tokens, reject atomically with no hidden fallback.
- Given MCP/CLI authoring of custom states and assigned items, actual output
  matches the UI's resolved styles and legend meanings.
- Given popover Apply/Cancel/Escape/keyboard/theme/narrow use, preserve drafts,
  input ownership, focus and one-edit history; no underlying shortcut mutation.

Update guide/manual with advanced page scope, defaults, meanings, CRUD/remapping,
legend behavior, supported paint fields and copyable MCP/CLI examples.
No installed0.5.1 capability claim.

## Boundaries

No global style library, cross-page inheritance, arbitrary CSS/SVG/code,
automatic semantic classification, dependency, migration, packaging, version,
release/install or Git delivery. Schema/public fields are limited to RFD005.
